---
title: "Job-Log Card"
slug: JobLogCard
---

A job-log card starts a long-running job and shows its progress as it runs. It has a small form and a log pane.
Submitting the form posts to your endpoint, which starts an `AsyncJobsMixin` job and returns its `AsyncJobRef`. The
card then streams the job's progress lines and shows the outcome when the job ends. The script is
`juneau-joblog.js`, and `<@page>` loads it for you.

```html
<@card type="job-log" id="rebuild" title="Rebuild index">
{ submit: { endpoint: '/ops/jobs/rebuild', submitLabel: 'Rebuild',
            fields: [ { name: 'shards', label: 'Shards', type: 'number', default: 4 } ] },
  urlParam: 'job' }
</@card>
```

From Java there is no typed builder; use `CardSpec`:

```java
page.card(CardSpec.of("job-log", "rebuild").title("Rebuild index")
	.body("submit", Map.of("endpoint", "/ops/jobs/rebuild", "submitLabel", "Rebuild"))
	.body("urlParam", "job"));
```

## The endpoint

The submit endpoint receives the field values as JSON, plus an `idempotencyKey` that the card mints fresh for every
submit, and returns `AsyncJobRef.of(job)`. Because the card owns that key, a form field named `idempotencyKey` is
rejected when the page renders. Report progress with `job.progress("...")`; each call becomes one line in the log pane,
shown as text. The job's final `ActionResult` sets the banner:

| Outcome | Banner |
|---|---|
| `success` | Done. |
| `failure` | The job failed. |
| `refusal` | The job was refused. |
| `cancelled` | Cancelled. |
| `cancelled-after-effect` | Cancelled after the job had already made changes. |
| `unknown` | The job ended with an unknown outcome. |

The result's `message`, if any, follows the banner text. A `success` banner is styled as ok and every other outcome
as an error.

## Body keys

| Key | Meaning |
|---|---|
| `submit.endpoint` | Required. A same-origin path (no scheme, no `//` prefix, no `..` segment). |
| `submit.method` | `POST` (default) or `PUT`. |
| `submit.fields` | Form fields: `{ name, label, type, placeholder, required, default }`. `name` is required and `type` is `text`, `textarea` or `number`; any other type, or any other key, fails the page. A name of `idempotencyKey` is reserved. A missing required field shows an error banner and focuses the field; nothing is sent. |
| `submit.submitLabel` | The button text (default "Run"). |
| `height` | The log pane height in pixels, at least 80 (default 240). |
| `urlParam` | Mirror the running job id into this URL query parameter (a name matching `[A-Za-z][A-Za-z0-9_-]*`). |
| `clearOnSubmit` | Clear the previous run's log on a new submit: `true` (default) or `false`. |

## Cancel and reload

While a job runs, the button becomes **Cancel**, which posts to the job's `cancelUrl`; it is disabled when the
`AsyncJobRef` has no `cancelUrl`. Whichever ends the job first, the cancel response or the stream's result, sets the
banner. A cancel that fails shows its message in an error banner and leaves the job running.

The card remembers the running job in the browser's local storage. After a reload it reconnects to the job's
stream, which replays the progress so far; lines already on screen are not shown twice, and the same holds when the
browser reconnects a dropped stream by itself. With `urlParam`, it reconnects only when the URL names the same job. A
job the server no longer knows (or any stream that closes before delivering a single event, which includes a 429 or 5xx on attach) shows "Job not found; it may have finished or the server restarted." in the log pane
and returns the form to its idle state, and the stored job and URL parameter are cleared. If the stream drops for
good after it had delivered events, a warning banner says the job may still be running and to reload to reattach.
A browser without `EventSource` shows a warning that live progress is unavailable. **New run** forgets the finished
job and shows the form again.

## Security

The `streamUrl` and `cancelUrl` of the returned `AsyncJobRef` must resolve to the page's own origin, because the cancel
request carries the console's CSRF token. A ref from another origin is refused with E-JS-77. The same check applies
to a job ref read back from local storage after a reload, except that a bad stored ref is silently ignored (no E-JS-77) and the card starts idle. `submit.endpoint` is checked at render by the same
same-origin-path rule as `ChartDef` hrefs, and again in the browser before each submit, because that request carries
the CSRF token too: an endpoint that resolves to another origin, contains a backslash or starts with a space is refused
with E-JS-81 and nothing is sent.

## Accessibility

The log pane is `role="log"` with `aria-live="polite"` and takes keyboard focus, so a screen reader reads new lines as
they arrive. Errors, including a rejected submit, a missing required field and a failed job, appear in a banner with
`role="alert"`, so they are announced at once, and again if the same error comes back. The ok and warning banners (a successful job, an interrupted stream, a
browser without `EventSource`) have no role and are announced politely through the console's status region instead.
When the Run/Cancel button changes or disappears, keyboard focus moves to the control that replaces it, or to the log
pane, rather than falling back to the page.

## Errors

| Code | When |
|---|---|
| E-JS-77 | The submit response is not a valid `AsyncJobRef`: `jobId` or `streamUrl` is missing, or `streamUrl` or `cancelUrl` is not same-origin. Shown in an alert banner above the form, which stays usable. |
| E-JS-78 | The stream's `result` event could not be parsed, or has no `outcome`. Shown in the alert banner. |
| E-JS-81 | `submit.endpoint` is not a same-origin path. Shown in the alert banner; nothing is sent. |

Java checks the card body when the page renders: a missing `submit.endpoint`, an unknown key in the body, in `submit`
or in a field, a cross-origin `submit.endpoint`, a `submit.method` other than `POST` or `PUT`, a field without a
`name` or with a `type` other than `text`, `textarea` or `number`, a `height` below 80, a malformed `urlParam`, a
`clearOnSubmit` that isn't a boolean, a field named `idempotencyKey`, and a `src=` or `template=` on the card all fail
the page.

A rejected submit (for example a job limit) shows the server's message above the form.

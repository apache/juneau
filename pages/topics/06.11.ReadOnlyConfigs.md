The following settings can be used to create read-only `Config` objects:

<tree>
<node-0><java-class><a href="/site/apidocs/org/apache/juneau/config/Config.Builder.html" target="_blank">Config.Builder</a></java-class></node-0>
<node-1><java-method><a href="/site/apidocs/org/apache/juneau/config/Config.Builder.html#readOnly()" target="_blank">readOnly()</a></java-method></node-1>
</tree>

:::tip Example
```java
// Create a read-only config
Config config = Config.create("MyConfig.cfg").readOnly().build();
```
:::

This causes all methods that make modifications to throw <a href="https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/UnsupportedOperationException.html" target="_blank">UnsupportedOperationException</a>.

## Affected methods

The following `Config` methods throw `UnsupportedOperationException` ("Cannot call this method on a read-only configuration.") on a read-only config:

- `set(...)` (all overloads) and `remove(String)`
- `setSection(...)` and `removeSection(String)`
- `setImport(...)` and `removeImport(String, String)`
- `load(...)` (all overloads)
- `applyMods()`
- `commit()` and `rollback()`

Read methods such as `get(String)`, `getString(String)`, `getSection(String)`, `writeTo(Writer)` and `toString()` work normally.

:::tip Example
```java
Config config = Config.create("MyConfig.cfg").readOnly().build();

String name = config.getString("General/name");   // OK

try {
    config.set("General/name", "new value");       // Throws
} catch (UnsupportedOperationException e) {
    // Expected.
}
```
:::

## Default

If `readOnly()` is not called, the default is the first value found:

1. System property `Config.readOnly`
2. Environment variable `CONFIG_READONLY`
3. `false`

Read-only applies to the `Config` object only.
If the store reports an external change to the underlying file (for example a `FileStore` with the watcher enabled; see [FileStore](/docs/topics/FileStore)),
the config still picks it up.

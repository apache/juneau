---
title: "Choosing a REST Client"
slug: ChoosingARestClient
---

Juneau 10 ships **two** REST client stacks in the same release. Both are supported; they differ in
which HTTP library they are built on and how much of the Juneau API surface they expose.

| | Next-Generation (NG) client | Classic client |
|---|---|---|
| Maven artifact | `juneau-rest-client` | `juneau-rest-client-classic` |
| Package | `org.apache.juneau.rest.client` | `org.apache.juneau.rest.client.classic` |
| HTTP library | Pluggable [transport](/docs/topics/HttpTransportAdapters); JDK `HttpClient` by default (no third-party dependencies) | Apache HttpClient 4.5 only |
| Extends `HttpClient` | No | Yes (`implements org.apache.http.client.HttpClient`) |
| HTTP types | `org.apache.juneau.http.*` | `org.apache.juneau.http.classic.*` (HttpCore-based) |
| Mock client | `org.apache.juneau.rest.mock.MockRestClient` | `org.apache.juneau.rest.mock.classic.MockRestClient` |
| SSRF guard for `@Remote` / `@Url` | Yes, with per-hop redirect re-validation ([NG Security](/docs/topics/NgClientSecurity)) | Yes (classic guard classes) |
| Stability | Canonical; marked beta until the next major release | Stable, unchanged from 9.x |

## Choose the NG client when...

- You are starting a new project.
- You want zero third-party dependencies (the JDK `HttpClient` transport is the default), or you want
  to pick OkHttp, Jetty, or Apache HttpClient 4.5/5 per deployment without changing application code.
- You want the typed response accessors, [assertions](/docs/topics/NgAssertions), and the
  [`BodyConverter`](/docs/topics/NgBodyConverters) extension point.
- You want serverless tests with the NG [`MockRestClient`](/docs/topics/NgMockRestClient).

## Choose the classic client when...

- You depend on `RestClient` *being* an Apache `HttpClient` (passing it to libraries that expect one,
  or customizing it through `HttpClientBuilder`).
- You have existing code that uses the classic fluent surface (`.json5()`, `.plainText()`, etc.) and
  you cannot migrate yet.
- You need strict binary stability for the current release line.

Existing 9.x code keeps working by changing imports to the `.classic` packages; the full rename table
is in the [V10 Migration Guide](/docs/topics/V10MigrationGuide).

## Both in one project

The two clients can coexist in the same application, including both mock flavors (both live in the
`juneau-rest-mock` module). Migrate one call site at a time.

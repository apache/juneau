`juneau-run` is build tooling, not a library dependency. It ships `juneau_run.py`, a stdlib-only Python script that
wraps Maven, pytest, Playwright, Gradle, npm and Bazel runs. It parses each tool's output into steps, sub-steps and
test counts, and from those it draws a board console view, writes full and board logs, prints run-protocol
markers for a runner UI, and writes run-view events for the [Run View Region](/docs/topics/RunViewRegion) and the
[Terminal Region](/docs/topics/TerminalRegion). Juneau's own `test.py`, `push.py` and `release.py` run on it.

The module is `pom` packaging and attaches its files to `org.apache.juneau:juneau-run:<version>`:

| Type | Classifier | Contents |
|---|---|---|
| `py` | | `juneau_run.py`, the engine. |
| `zip` | | `bootstrap.py`, the `juneau_scripts` toolkit for push and release scripts, the pytest plugin and the Playwright reporter. |
| `py` | `pytest` | The pytest plugin on its own. |

It is not managed by `juneau-bom`; pin it at the Juneau version your build already uses. `mvn install` in the module
runs its unit tests (`python3 -m unittest`); `-DskipTests` skips them. PTY mode is POSIX only.

The [module README](https://github.com/apache/juneau/blob/master/juneau-run/README.md) is the full reference. The
wire formats are in
[run-protocol-v1.md](https://github.com/apache/juneau/blob/master/juneau-run/docs/run-protocol-v1.md) and
[prompt-protocol-v1.md](https://github.com/apache/juneau/blob/master/juneau-run/docs/prompt-protocol-v1.md).

## Running one command

```bash
python3 juneau_run.py [options] <tool> -- <cmd...>
```

`<tool>` picks the output parser: `maven`, `pytest`, `playwright`, `gradle`, `npm`, `bazel` or `generic`. Every option
comes before `<tool>`.

| Option | Effect |
|---|---|
| `--console full\|board\|none` | Where the tool's output goes (see [Console view](#console-view)). |
| `--full-log PATH`, `--board-log PATH` | The raw log, and the view's rows as plain text. |
| `--step ID`, `--title TEXT` | The step's id and title. |
| `--pty`, `--size COLSxROWS`, `--events PATH` | Run under a pseudo-terminal (see [PTY mode](#pty-mode-and-the-terminal-region)). |
| `--input stdin` | With `--pty`, copy this process's stdin to the tool's terminal. |
| `--prompts stdio` | With `--pty`, relay the job's prompt channel (see [Prompts](#prompts)). Not with `--input`. |

From a script, `run_tool(cmd, parser, step_id, title, ...)` does the same and returns the exit code, the time taken
and the test totals. When a script runs a command without naming a parser, it is picked from the command: `mvn` or
`mvnw` is `maven`, pytest (direct, `python -m pytest` or `uv run pytest`) is `pytest`, `playwright test` is
`playwright`, and so on, looking through `env`, `npx`, `pnpm`, `yarn` and `npm exec`. Quiet Maven (`-q`) and
anything unrecognized use `generic`.

## Console view

`JUNEAU_RUN_CONSOLE` (or `--console`) chooses the view:

- `full` (the default) prints the tool's output as it comes.
- `board` draws one row per step, with its time, a progress bar, counts and one line of summary. Each running unit
  (a Maven module, a pytest or Playwright test file, a check) gets a line under its row. Raw output goes to the full log.
- `none` draws nothing. Both of the others still write the logs.

The board view of a Maven run, part-way through and when it has finished:

![The board console view of a Maven run, part-way through](/topics/JuneauRun.ConsoleView.1.svg)

![The board console view of a finished Maven run](/topics/JuneauRun.ConsoleView.2.svg)

With `board` or `none` and no full log named, the full log defaults to
`~/.cache/juneau-run/<script>-<YYYYMMDD-HHMMSS>.log` (the newest 20 are kept), and the header prints the `tail -f`
command for it. `JUNEAU_RUN_DETAIL` (`summary`, `actionable`, `modules` or `all`; default `actionable`) sets how many
sub-rows a finished step keeps. Failures, prompts and the final `✅`/`❌`/`⚠` line show at every level. Off a terminal,
with `TERM=dumb` or with `JUNEAU_RUN_LIVE=0`, each row prints once when it ends; `NO_COLOR` turns off colour. Ctrl-C
and SIGTERM close the view and end the run as `cancelled` (exit 130). A display failure falls back to plainer output
and never fails the build.

### Progress bars

A test row's bar has one block per unit:

| Parser | One block by default | `bar=` choices |
|---|---|---|
| `maven` | a module | `"modules"` |
| `pytest` | a test file | `"files"`, `"tests"` |
| `playwright` | a test file | `"files"`, `"tests"` |

`bar=` on `run_tool`, `run.cmd`, `run.gate`, `tools.pytest` or `tools.playwright` picks another unit; a value the
parser doesn't offer raises `ValueError` before the command starts. A file block is added when its last test ends:
it fails if any test failed, is skipped if all were skipped, and passes otherwise. On a file bar the percent and time
estimate follow the tests run, so they move with every test.

Maven rows:

- **One module.** A build of a single project, a one-module tree or `-pl` without `--also-make`, draws as one
  module: one in-flight block and `0/1` while it runs, with the percent taken from the tests run against the
  history's expected count. It counts as `1/1` when it succeeds, so its history is usable for later estimates.
- **No tests.** A build that stops before `test` (only goals up to `test-compile`, or `-DskipTests`) still draws its
  module bar: each module counts when it finishes compiling, and the row shows no test totals.

The pytest and Playwright file blocks need the units' own progress lines:

- **pytest plugin.** `-p juneau_run_pytest` is added to every pytest run, with only the plugin's directory put on
  `PYTHONPATH`, so the suite under test never sees the engine. `JUNEAU_RUN_PYTEST_PLUGIN=0`, or `-p
  no:juneau_run_pytest` on the command, leaves it out.
- **Playwright reporter.** `juneau_run_playwright.cjs` is added through `PW_TEST_REPORTER`, which Playwright appends
  to the `reporter:` list in `playwright.config`, so the config's reporters still run. It draws a line per running
  test file, counts the bar once per test however often it is retried, and, with markers on and `RUN_ARTIFACTS` set,
  writes `<step>-playwright.json`. Outside a terminal it also sets `PLAYWRIGHT_HTML_OPEN=never`, so a failing run
  doesn't serve its html report and wait. It is left out with `JUNEAU_RUN_PLAYWRIGHT_REPORTER=0`, or when the command
  names its own `--reporter` or sets `PW_TEST_REPORTER`. `PW_TEST_REPORTER` is undocumented in Playwright: a version
  that ignores it runs as a plain run, and the step notes "Playwright reporter not loaded".

Without the plugin or the reporter, both bars count tests.

### Run history and estimates

Each run records per-step timings and test counts under `~/.cache/juneau-run/history/<repo>-<hash>/`, keyed by the
repository's git common directory, so branches and linked worktrees share one history. From it a running row shows
the expected test total (`41,200 / ~83,000 tests`), a percent and an estimated total time, and the view keeps an
Overall line for the whole run. An estimate changes only when a new one differs by more than 15 seconds or 10%,
whichever is larger, and is rounded by size.

| Variable | Effect |
|---|---|
| `JUNEAU_RUN_HISTORY=0` | No history: no percent, estimates or Overall line. |
| `JUNEAU_RUN_HISTORY_DIR` | Replaces `~/.cache/juneau-run/history`. |
| `JUNEAU_RUN_HISTORY_KEY` | Replaces the per-repository key, so separate clones of one repository can share a history. |

## Run-protocol markers

With `RUN_MARKERS=1`, stdout carries one `##run <json>` line per event (`run`, `step`, `end`, `tests`, `report`,
`note`, `done`) for a runner UI, and no view is drawn there; the board log still gets the rows. With it unset the
output is what the tool prints. A process started by the one that owns the run (`JUNEAU_RUN_ACTIVE=1`) adds steps but
never its own `run` or `done`. When `RUN_ARTIFACTS` is set, test reports are copied under
`$RUN_ARTIFACTS/reports/<step>/`, so a later `clean` cannot remove them.

`JUNEAU_RUN_MARKERS_FILE` sends the same markers to a file while the console view still draws, and `JUNEAU_RUN_RESULT`
names a file that gets the run's outcome as JSON when it ends. A tool that starts a script uses them to follow it; see
[Driving a Run from Another Tool](/docs/topics/DrivingARun).

## PTY mode and the terminal region

```bash
python3 juneau_run.py --pty --full-log LOG --events EVENTS [--size COLSxROWS] <tool> -- <cmd...>
```

The tool runs under a pseudo-terminal of a fixed size (default `120x40`), so tools that colour, redraw or draw
progress bars behave as they do in a terminal. `LOG` gets the tool's bytes unchanged, with a `LOG.size` sidecar, and
`EVENTS` gets run-view events whose `rawOffset` points into `LOG`, whether or not markers are on. This is what
[`TerminalProcess`](/docs/topics/TerminalRegion#running-a-command-terminalprocess) runs; the terminal region shows
`LOG` and the run view shows `EVENTS`. The tool's exit code passes through; a tool killed by signal *n* exits `128+n`
with a warning note, and one that cannot start exits 127.

## Prompts

`juneau_scripts.prompt` asks for input (`text`, `secret`, `confirm`, `choice`, `form` and `email`). When the host
started the script with the two prompt descriptors, each prompt is a JSON line to the host and the answer comes back
on the other descriptor; otherwise it prompts on the terminal. `juneau_run.py --pty --prompts stdio` relays that
channel over its own stdout and stdin: the job's prompt lines go to stdout, and lines on stdin go back to the job.
EOF on stdin means the host has gone, and the job is cancelled. A secret answer is never logged, published,
checkpointed or put on a command line.

## Cancelling

Every tool runs in a process group of its own. On Ctrl-C or SIGTERM the whole group gets SIGTERM, then SIGKILL for
whatever is left after a grace period (10 seconds when a prompt host has gone), so child processes such as forked test
JVMs or browsers don't outlive the run. A tool given the real terminal (markers off, no capture) holds the terminal's
foreground while it runs. A `^Z` stops the run as a whole, and resuming it gives the tool the terminal again.

## Writing push and release scripts

`juneau_scripts`, in the `zip`, holds the helpers a push or release script would otherwise rewrite: git readers and
writers, a session with exit codes (0, 1, or 130 for a cancel), tool runners, a step registry with resume, locks,
notifications and prompts. Policy stays in the script, and the toolkit never runs `git add`. Vendor the loader once:

```bash
unzip -p ~/.m2/repository/org/apache/juneau/juneau-run/<v>/juneau-run-<v>.zip bootstrap.py > scripts/bootstrap.py
```

```python
from bootstrap import load
jr, js = load(pom="pom.xml")
from juneau_scripts import git, run, tools

def main(args):
    with run.session("push", bell=True) as s:
        s.require(tools.maven(["verify"], title="Build and test"))
        s.require(git.commit_index(args.message))
        s.require(git.push(set_upstream=True))
```

`load()` finds the toolkit through `JUNEAU_SCRIPTS_ZIP` and `JUNEAU_RUN_PY`, then the source tree under the pom's
directory, then the local Maven repository, and otherwise copies it there with `mvn dependency:copy`. With markers off
and no terminal the same code prints plain lines, so it works in CI. Each module's docstring is its reference.

## In the Juneau build

[`test.py`](/docs/developer-info/ScriptTest), [`push.py`](/docs/developer-info/ScriptPush) and
[`release.py`](/docs/developer-info/ScriptRelease) load `juneau_run.py` straight from
`juneau-run/src/main/python/`. With `--console board` (or `JUNEAU_RUN_CONSOLE=board`), `test.py` draws the
Compile through Browser tests rows, and `push.py` runs `test.py` and adds its own rows around them. A full `push.py` run
shows these rows, in this order:

| Row | Drawn by | What it runs |
|---|---|---|
| Prechecks | `push.py` | The committer identity, no unreviewed changes, and a branch that isn't behind its upstream, before any gate. |
| Tracker | `push.py` | With `--tracker-audit`, the work-tracker audit gate. |
| Tags | `push.py` | `check-container-tags.py`, the container test tags. |
| BOM | `push.py` | `check-bom-completeness.py`, that `juneau-bom` matches the reactor. |
| Compile | `test.py` | `mvn clean install -DskipTests`. |
| Java tests | `test.py` | The Maven test run, one block per module. |
| Perf | `test.py` | The perf guard: the suite's and each module's wall clock against `perf-baseline.txt`. |
| Python tests | `test.py` | `scripts/tests`, the tooling's own pytest suite, with the current test file shown under the row. |
| Browser tests | `test.py` | The `*_BrowserTest` classes under `-Pjs-tests`. The row always shows, marked skipped with the reason when the tests don't run. |
| Timing | `push.py` | The timing regression report from the run history. Advisory: it never stops the push. |
| Install | `push.py` | `mvn clean package install -DskipTests`, marked skipped when `test.py` has already installed. |
| Commit | `push.py` | Commits what is staged in juneau. |
| Push | `push.py` | Pushes juneau to its upstream. |
| Docs build | `push.py` | When juneau-docs has changes, `build-docs.py --skip-maven` as a smoke check before its commit. |
| Docs | `push.py` | Commits what is staged in juneau-docs. |
| Docs push | `push.py` | Pushes juneau-docs to its upstream. |

`--detail` on all three scripts sets the detail level.

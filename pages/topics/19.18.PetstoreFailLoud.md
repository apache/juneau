A console page that is misconfigured must fail where the mistake is, with a message that names it. It must not render
a half-working page, drop a card, or fall back to a default without telling anyone. The petstore calls this
*FailLoud*. This page explains the rule, shows how the tests exercise it, and lists every case the petstore pins.

## What FailLoud means

When a template or a `PageSpec` is wrong, the render stops with HTTP 500 and the body names the directive, the id and
what to do instead. For example, a badge declared twice, a nav path that does not exist, a body key that is
reserved, or a `bytesUrl` that points off-site. The message is the contract. The tests assert the text of the
message, not just the status, so a rewording that loses the useful part fails the build.

Two things are worth knowing before you read the table:

- **Most cases pin a message, not a code.** The reason codes the console used to print (the `E-B` series for the
  server-side directives) were replaced by plain messages, so the table lists a code only where an assertion still
  pins one. A code that appears only in a comment does not count.
- **Some failures are client-side.** The server renders the page successfully and the browser script reports the
  problem. Those are covered separately, below the main table.

## How the tests are built

`PetstoreFailLoud_Test` renders small fixture templates through three hosts. Each is a minimal REST servlet with the
console FreeMarker mixin:

- `FixtureHost` renders `failloud/<name>.ftlh` inside the production `base.ftlh` chrome, so a fixture is a page in the
  real petstore frame. It also has two builder routes (`/s/badge-duplicate` and `/s/facts-duplicate`) for mistakes
  that start in a `PageSpec`, and it registers the petstore's custom card type so the custom-card cases run for real.
- `DevHost` is the same chrome with dev mode on. Dev mode validates each page contract against its schema before
  writing it, so a bad contract is rejected on the server instead of in the browser.
- `ChromeHost` uses a small test chrome that includes one fixture. The directives `<@navigation>`, `<@badge>` and
  `<@facts>` are legal only in a chrome, never in a page, so cases about them need a chrome to put them in.

The fixtures live under `src/test/resources/org/apache/juneau/petstore/console/failloud/`. Each test renders one,
asserts a 500 and checks that the body contains the expected message.

A manifest, `docs-catalogue.txt`, lists every FailLoud test with its fixture and any pinned code. A second test,
`PetstoreDocsCatalogue_Test`, fails the build when a FailLoud test is added without a manifest row, when a catalogued
test or fixture disappears, or (when pointed at a docs checkout) when this page stops mentioning a test id or code.
That is why every test id below appears in the table.

Notes on the table:

- There is no `a03` or `a09`. Neither exists in the current test class.
- `a05` and `a06` are the same rule seen from two places: `under=` is an addition made from a page or the console
  root, never from inside the navigation itself.
- `a08` is catalogued even though it is disabled, because the rule is real and the table should say where it is
  covered.

## Client-side codes pinned by browser tests

Some mistakes can only be detected in the browser, by the console scripts. The server returns 200 and the script
raises a coded error. These codes are pinned by the petstore's browser tests:

| Code | Test | What is asserted |
|---|---|---|
| E-JS-12 | `PetstoreCustomCard_BrowserTest` | Registering a card type that is already registered (`kpi`) reports `E-JS-12 card type 'kpi' is already registered` |
| E-JS-62 | `PetstoreDashboard_BrowserTest` | A data source or chart fetch that fails reports `E-JS-62` with the source or card id |
| E-B4 | `ThemesRest_Test` | Asserted **absent**: a nameless `<@theme>` must not raise a theme error, so the page renders |

## Adding a case

1. Add a fixture under `failloud/`, or a route on one of the hosts if the mistake starts in a `PageSpec`.
2. Add a test to `PetstoreFailLoud_Test` that asserts the full message (or a stable prefix, where the message ends in a
   list that changes with the nav).
3. Add a row to `docs-catalogue.txt` and to the table above. `PetstoreDocsCatalogue_Test` fails until both exist.

Source: `PetstoreFailLoud_Test` and the `failloud` fixtures under
`juneau-petstore/juneau-petstore-core/src/test/`; the manifest `docs-catalogue.txt` under the matching test resources;
the framework side in the `console-ui-freemarker` module's `ConsoleDirective_Errors_Test`.

Tests: `PetstoreFailLoud_Test`, `PetstoreDocsCatalogue_Test`, `PetstoreCustomCard_BrowserTest`,
`PetstoreDashboard_BrowserTest` and `ThemesRest_Test`.

The main class for performing variable resolution is <a href="/site/apidocs/org/apache/juneau/commons/svl/VarResolver.html" target="_blank">VarResolver</a>.
A resolver holds a set of <a href="/site/apidocs/org/apache/juneau/commons/svl/Var.html" target="_blank">Var</a> classes and context objects, and replaces each `$X{key}` in a string with the value its variable produces.

## When to use it

Use your own `VarResolver` when you need variables beyond the defaults, or variables that depend on application objects such as a `Config`.
For plain `$S{...}` and `$E{...}` lookups, the shared [VarResolver.DEFAULT](/docs/topics/DefaultVarResolver) is enough.
Resolvers are immutable; to add variables, copy an existing one with `copy()` and build the copy.

## Example

```java
import org.apache.juneau.commons.svl.*;

public class VarResolverExample {

    // A bean that a variable can look up through the session.
    public static class Greeting {
        public String text = "Hello";
    }

    // The $G{name} variable reads the Greeting bean from the session.
    public static class GreetingVar extends SimpleVar {
        public GreetingVar() {
            super("G");
        }

        @Override
        public String resolve(VarResolverSession session, String key) {
            return session.getBean(Greeting.class).map(g -> g.text).orElse("Hi") + ", " + key;
        }
    }

    public static void main(String[] args) throws Exception {
        // Copy the default resolver (which has $S and $E), add $G, and register the bean for all sessions.
        VarResolver resolver = VarResolver.DEFAULT
            .copy()
            .vars(GreetingVar.class)
            .bean(Greeting.class, new Greeting())
            .build();

        System.out.println(resolver.resolve("$G{World}! Java is $S{java.specification.version}."));

        // A session can override a bean for one resolution only.
        Greeting formal = new Greeting();
        formal.text = "Good day";
        System.out.println(resolver.createSession().bean(Greeting.class, formal).resolve("$G{World}"));
    }
}
```

## Options

Var resolvers can rely on the existence of other objects.
For example, <a href="/site/apidocs/org/apache/juneau/config/vars/ConfigVar.html" target="_blank">ConfigVar</a> relies on the existence of a <a href="/site/apidocs/org/apache/juneau/config/Config.html" target="_blank">Config</a>.
This is accomplished through the following methods:

Beans are accessible through the following method:

<tree>
<node-0><java-method><a href="/site/apidocs/org/apache/juneau/commons/svl/VarResolverSession.html#getBean(java.lang.Class)" target="_blank">VarResolverSession.getBean(Class)</a></java-method></node-0>

| Builder method | Effect |
|---|---|
| `defaultVars()` | Add the default variables (`$S`, `$E` and the others). `VarResolver.DEFAULT` already has them. |
| `vars(Class...)` / `vars(Var...)` | Add variable classes or instances. |
| `functions(...)` / `defaultFunctions()` | Add `#{...}` functions; see [Simple Variable Language](/docs/topics/SimpleVariableLanguage). |
| `bean(Class, T)` | Register a bean that variables read through the session. |
| `build()` | Create the resolver. |

Var resolvers can be cloned and extended by using the <a href="/site/apidocs/org/apache/juneau/commons/svl/VarResolver.html#copy()" target="_blank">VarResolver.copy()</a> method.
Cloning a resolver will copy it's <a href="/site/apidocs/org/apache/juneau/commons/svl/Var.html" target="_blank">Var</a> class names and context objects.

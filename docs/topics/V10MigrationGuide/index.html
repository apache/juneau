v10.0 Migration Guide

The following guide can be used to help migrate your code to v10.0. Note that you can also refer to the Release Notes for changes as well.

This guide covers all breaking changes introduced since v9.1, including changes that were originally developed under the v9.5.0 label (a release that was never shipped — it was renamed to v10.0.0). Teams upgrading from 8.x, 9.1, or any earlier version can use this as a single authoritative reference.

Package Renames​

REST Server Package Rename: org.apache.juneau.rest.* → org.apache.juneau.rest.server.*​

All server-side REST classes have been moved from org.apache.juneau.rest to org.apache.juneau.rest.server. This affects the core module as well as all server add-on modules (-auth-jwt, -mcp, -metrics-micrometer, -auth-oauth, -auth-oidc-rp, -tracing-otel, -rdf, -reactive, -reactive-reactor, -auth-saml, -springboot, -view-*). Client-side classes (org.apache.juneau.rest.client.*) and mock testing classes (org.apache.juneau.rest.mock.*) are not affected. Additionally, the juneau-rest-server-reactive-reactor module had its package renamed from org.apache.juneau.rest.server.reactor → org.apache.juneau.rest.server.reactive.reactor to match the new module name.

Migration: Update all import org.apache.juneau.rest.X → import org.apache.juneau.rest.server.X in user code. IDE global find-replace on the import prefix is sufficient.

Marshall Package Rename: org.apache.juneau.* (marshall classes) → org.apache.juneau.marshall.*​

All classes from the juneau-marshall and juneau-marshall-rdf modules have been moved from the root org.apache.juneau namespace into the org.apache.juneau.marshall namespace. This includes all format-specific subpackages (json, xml, html, yaml, csv, uon, urlencoding, msgpack, cbor, bson, json5, jsonl, jsonschema, markdown, plaintext, oapi, proto, soap, sse, parquet, toml, hocon, hjson, ini, jcs, serializer, parser, marshaller) and the RDF/Jena subpackage (org.apache.juneau.jena → org.apache.juneau.marshall.jena). Classes from other modules at the org.apache.juneau.* level (commons, bean, microservice, rest) are not affected.

Migration: Update all import org.apache.juneau.X → import org.apache.juneau.marshall.X where X is a class or subpackage from the marshall module. IDE global find-replace on the org.apache.juneau. prefix filtered to affected subpackages is the safest approach.

MarshalledMap / MarshalledList + Json5Map / Json5List​

The generic-model collection hierarchy has been refactored. JsonMap / JsonList are no longer the one-size-fits-all generic-model types: they are now strict-JSON-flavored subclasses of a new neutral, marshaller-agnostic base (MarshalledMap / MarshalledList), with JSON5-flavored siblings (Json5Map / Json5List) carrying the historical JSON5 behavior. Parser sessions now produce flavored maps / lists based on the parser's language, which changes the runtime type returned by parser.parse(text, Object.class) for every parser other than JsonParser.

Serializer / Parser Builder CRTP Self-Type​

Serializer / Parser builder subclasses no longer need to override fluent setters for covariant return types — the CRTP SELF self-type on SerializerBuilder<SELF> / ParserBuilder<SELF> handles covariant returns automatically. Remove any override boilerplate that existed solely to narrow the return type; the base setters already return the correct concrete builder type.

Serializer.serialize(...) → write(...) / Parser.parse(...) → read(...) Rename​

The two core marshalling entry-point methods were renamed for symmetry with the read / write verbs the Marshaller facade already exposed (Marshaller.read(...) / Marshaller.write(...)). After the rename the facade and the underlying types finally use the same verbs — Marshaller.read delegates to Parser.read, and Marshaller.write delegates to Serializer.write.

This is a hard rename — the old serialize / parse names are gone with no @Deprecated delegating aliases — and it cascades through the session classes, the abstract format hooks, the parseInto* / parseArgs family, the HTTP-part marshalling family, and the record / token streaming interfaces.

Serializer / Parser I/O Narrowed to Streams (File / StringBuilder Dropped)​

The core serialize/parse I/O surface now accepts only Reader / Writer / InputStream / OutputStream (plus the scalar String / byte[] / CharSequence shortcut forms). The File and StringBuilder instanceof branches were removed from the internal SerializerPipe / ParserPipe plumbing, so passing a File or StringBuilder to Serializer.write(Object, Object), Parser.read(Object, ...), the token/record streaming methods (writeTokens / readTokens / writeRecords / writeArrayRecords), or any session createPipe(...) now throws at runtime. Because these methods are typed Object, callers passing the dropped forms still compile — the change surfaces at runtime as "Cannot convert object of type ... to a Writer/OutputStream/InputStream".

Utils Grab-Bag Removed → Shorts Facade + Domain Classes​

The org.apache.juneau.commons.utils.Utils grab-bag class has been deleted entirely — there is no deprecated delegator and no slimmed remnant. Its terse one/two-letter methods were split into two tiers:

  • Terse aliases now live in a single new facade, org.apache.juneau.commons.utils.Shorts. Every alias is a one-line delegation to a canonical, fully-descriptive method on a domain class.
  • Canonical logic lives in the domain classes: the new org.apache.juneau.commons.utils.ObjectUtils (null/empty checks, equality, comparison, coalescing, boolean folds, identity/stringify, optionals, and the abs/isBetween/isNotMinusOne numeric helpers), plus the existing StringUtils, CollectionUtils, ClassUtils, ThrowableUtils, IoUtils, FileUtils, and SystemUtils.

Migration: replace the wildcard static import and keep typing the same short tokens:

// Before
import static org.apache.juneau.commons.utils.Utils.*;

// After
import static org.apache.juneau.commons.utils.Shorts.*;

Most short names are unchanged (nn, n, eq, neq, h, id, s, r, cn, cns, f, cmp, lt, gte, uc, lc, o, oe, sz, …). The renames, relocations, and behavioral changes to be aware of:

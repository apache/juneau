27  /**
28   * The request-authenticity half of a loopback application's write protection: decides whether a request came from
29   * the page this process served, and refuses it when it did not.
30   *
31   * <h5 class='section'>What this answers, and what it does not</h5>
32   * <p>
33   * An application bound to <c>127.0.0.1</c> is reachable only from this host, but "reachable only from this host"
34   * is not an authorization boundary &mdash; every browser the user has open is on this host, and any page in any of
35   * them can attempt a request to the port.  This class answers exactly one question:
36   * <p class='bcode'>
37   * 	Did this request come from the page this process served?
38   * </p>
39   * <p>
40   * It does <b>not</b> answer <i>did the user mean it</i>.  A user who has the application's own page open, and who
41   * is induced to click something on it, produces a request that passes every check here.  That is a question of
42   * intent, and it needs a separate, independent mechanism &mdash; a typed confirmation, an arming gate, a
43   * per-action phrase naming the specific target.  <b>The two gates are deliberately not combined, in this class or
44   * in its naming.</b>  Treating an intent gate as though it authenticated the request, or this boundary as though
45   * it established intent, is the specific confusion this separation exists to prevent: an application with only an
46   * arming gate is forgeable by any page in the browser, and an application with only this boundary will faithfully
47   * execute whatever its own page was tricked into asking for.
48   *
49   * <h5 class='section'>The checks</h5>
50   * <table class='styled'>
51   * 	<tr><th>Check</th><th>Applies to</th><th>Rule</th><th>Rejection</th></tr>
52   * 	<tr>
53   * 		<td>{@code Host}</td><td><b>every</b> request</td>
54   * 		<td>equals the configured authority exactly (over HTTP/2, the {@code :authority}; see below)</td>
55   * 		<td>421 Misdirected Request</td>
56   * 	</tr>
57   * 	<tr>
58   * 		<td>{@code Origin}</td><td>state-changing requests</td>
59   * 		<td>present, and exactly <c>http://&lt;authority&gt;</c></td>
60   * 		<td>403 Forbidden</td>
61   * 	</tr>
62   * 	<tr>
63   * 		<td>{@code Sec-Fetch-Site}</td><td>state-changing requests</td>
64   * 		<td>absent, or exactly <c>same-origin</c></td>
65   * 		<td>403 Forbidden</td>
66   * 	</tr>
67   * 	<tr>
68   * 		<td>{@code Content-Type}</td><td>state-changing requests</td>
69   * 		<td>base type is exactly <c>application/json</c></td>
70   * 		<td>415 Unsupported Media Type</td>
71   * 	</tr>
72   * 	<tr>
73   * 		<td>CSRF token</td><td>state-changing requests</td>
74   * 		<td>the configured header equals the process's {@link SynchronizerToken}</td>
75   * 		<td>403 Forbidden</td>
76   * 	</tr>
77   * </table>
78   *
79   * <p>
80   * A request is state-changing when its <b>effective</b> method is not safe
81   * ({@link MethodSafety#effectiveMethod(String, String, java.util.function.UnaryOperator)}): a {@code GET} carrying
82   * {@code ?method=DELETE} or an {@code X-HTTP-Method-Override: PUT} header takes the write checks, whether or not the
83   * resource it reaches would honour the override.
84   *
85   * <h5 class='section'>HTTP/2</h5>
86   * <p>
87   * An HTTP/2 request has no {@code Host} header; the container surfaces its {@code :authority} only as
88   * {@link HttpServletRequest#getServerName()} and {@link HttpServletRequest#getServerPort()}.  A request with no
89   * {@code Host} whose {@link HttpServletRequest#getProtocol()} is exactly {@code HTTP/2.0} is therefore judged on
90   * that server name and port, compared as a parsed host and port (an absent port is {@code 80}) rather than as text.
91   * A request that carries a {@code Host} header is compared as written, as always.  A WebSocket handshake carried over
92   * HTTP/2 (RFC 8441) is judged the same way, on the authority of its request URI, through
93   * {@link #acceptsHandshakeHost(HandshakeHosts, String)}.
94   * <p>
95   * <b>Residual risk.</b>  When an HTTP/2 request names no {@code :authority} at all, containers fill the server name
96   * with their own bound address, which is this boundary's authority when it is bound to loopback.  A browser always
97   * sends {@code :authority}, so only a non-browser client can provoke this, and such a client must still present the
98   * {@code Origin} and token.
99   *
100  * <h5 class='section'>Why each check is present</h5>
101  * <p>
102  * <b>{@code Host} on every request, not only writes.</b>  This is the check that defeats DNS rebinding, and it is
103  * the reason the boundary cannot be scoped to the write path.  An attacker serves a page from
104  * <c>http://evil.example</c> with a very short DNS TTL, then re-resolves that name to <c>127.0.0.1</c>.  Requests
105  * the page then makes to <c>http://evil.example/...</c> are <i>same-origin</i> from the browser's point of view:
106  * no CORS, no preflight, {@code Origin} is the page's own origin and therefore consistent, and the response body
107  * is readable.  Neither origin checking nor a CSRF token stops this &mdash; the page can simply fetch this
108  * application's own HTML and scrape the token out of it.  What the attacker cannot change is the {@code Host}
109  * header, which after rebinding still carries <c>evil.example</c>.
110  * <p>
111  * Restricting that check to writes would leave every read surface open to the one attack it exists to stop, and a
112  * rebound page that can read the application's data tables is already an exfiltration problem whether or not it
113  * can write.
114  * <p>
115  * <b>{@code Origin} on writes.</b>  Browsers set it on every cross-origin request and on same-origin POSTs, and
116  * page JavaScript cannot forge it.  An absent {@code Origin} is a rejection rather than a pass, so a client that
117  * simply omits the header does not thereby skip the check.
118  * <p>
119  * <b>A JSON-only content type on writes.</b>  The three form-encodable content types
120  * (<c>application/x-www-form-urlencoded</c>, <c>multipart/form-data</c>, <c>text/plain</c>) are precisely the
121  * ones a cross-origin request may use without a preflight, which is what makes a plain cross-origin
122  * <c>&lt;form&gt;</c> POST possible with no JavaScript at all.  Refusing them forces any cross-origin caller into
123  * a preflight, which this application never answers with CORS headers, so the real request is never sent.
124  * <p>
125  * <b>{@code Sec-Fetch-Site} on writes.</b>  Tolerates absence, so a non-browser client used during development is
126  * not broken, and rejects any present-but-wrong value.  It adds nothing against a local process, which can set
127  * the header freely; it is here because it is one line and closes a browser-side gap cheaply.
128  * <p>
129  * <b>A CSRF token on writes.</b>  A server-held {@link SynchronizerToken}, embedded in the served page.  See that
130  * class for why a double-submit cookie is unsound on a loopback port.
131  *
132  * <h5 class='section'>One canonical origin</h5>
133  * <p>
134  * The authority is a single exact spelling.  If the application is reached at <c>127.0.0.1:8790</c> then
135  * <c>localhost:8790</c> is <b>not</b> accepted, and vice versa.  Accepting both doubles the surface for no
136  * benefit, and an application that links only to the spelling it accepts never notices the difference.
137  *
138  * <h5 class='section'>What this does not defend against</h5>
139  * <p>
140  * These are accepted residual risks, not oversights.  Stating them plainly matters, because a boundary described
141  * as stopping more than it does invites the wrong decisions to be built on top of it.
142  * <ul>
143  * 	<li><b>A local process running as the same user is not defended against, and cannot be.</b>  It already holds
144  * 		every credential this application holds &mdash; the same keychain entries, the same config files, the same
145  * 		environment.  It does not need this application to do anything.  Nor does any of the machinery here
146  * 		obstruct it: everything the browser must be able to present in order for the UI to work is equally
147  * 		obtainable by a local HTTP client that fetches the same page first and reads the token out of it.  A
148  * 		shared secret cannot separate "our page" from "a local program impersonating our page", because both are
149  * 		given the secret by the same server.  This boundary raises the bar for pages in a browser; against a
150  * 		same-user local process it is not a control at all.
151  * 	<li><b>A malicious or compromised browser extension is not defended against.</b>  An extension can read the
152  * 		page, read the token out of it, and issue requests as the page.  Every check here is satisfied from inside
153  * 		the page.
154  * 	<li><b>The human is not authenticated.</b>  There is no login.  The operating-system session is the
155  * 		authentication; whoever is at the keyboard is the user.
156  * 	<li><b>Intent is not established.</b>  See the first section: that is a separate gate's job.
157  * </ul>
158  *
159  * <h5 class='section'>Non-browser callers</h5>
160  * <p>
161  * There is deliberately no path-exemption or trusted-caller list.  A non-browser client that must write &mdash;
162  * including a process calling back into its own loopback port &mdash; presents the same {@code Host},
163  * {@code Origin}, content type and token as the page does.  An exemption list is the shape of API that gets one
164  * more entry added under deadline pressure until it covers the endpoint that mattered, so the boundary does not
165  * offer one.
166  *
167  * <h5 class='section'>Example:</h5>
168  * <p class='bjava'>
169  * 	LoopbackBoundary <jv>boundary</jv> = LoopbackBoundary.<jsm>create</jsm>()
170  * 		.authority(<js>"127.0.0.1:8790"</js>)
171  * 		.token(SynchronizerToken.<jsm>generate</jsm>())
172  * 		.build();
173  *
174  * 	BoundaryResult <jv>result</jv> = <jv>boundary</jv>.check(<jv>request</jv>);
175  * 	<jk>if</jk> (! <jv>result</jv>.isAllowed())
176  * 		<jv>response</jv>.sendError(<jv>result</jv>.status(), <jv>result</jv>.message());
177  * </p>
178  *
179  * <h5 class='section'>See Also:</h5><ul>
180  * 	<li class='jic'>{@link RequestBoundary}
181  * 	<li class='jc'>{@link LoopbackBoundaryFilter}
182  * 	<li class='jc'>{@link SynchronizerToken}
183  * </ul>
184  *
185  * @since 10.0.0
186  */

229 	/**
230 	 * Applies the boundary to a request.
231 	 *
232 	 * @param req The request to check.  Must not be <jk>null</jk>.
233 	 * @return {@link BoundaryResult#ALLOWED} when every applicable check passed, else the first rejection encountered.
234 	 */
235 	@Override /* RequestBoundary */
236 	public BoundaryResult check(HttpServletRequest req) {
237 		reqnn("req", req);
238 
239 		// Host applies to every request; it is the DNS-rebinding check and a read is just as exfiltratable as a write.
240 		// A real Host is compared as written.  Only an HTTP/2 request with none (its :authority is the container's server
241 		// name and port) takes the parsed comparison.
242 		var host = req.getHeader("Host");
243 		var hostMatches = host != null ? ! neqic(host, authority)
244 			: BoundaryChecks.isSynthesisedHost(req) && matchesAuthority(BoundaryChecks.hostValues(req).get(0), "http");
245 		if (! hostMatches)
246 			return reject(BoundaryReason.HOST_MISMATCH, 421,
247 				"Request 'Host' does not match this server's expected authority '%s'.", authority);
248 
249 		// Judged on the method the request claims, so an override cannot carry a write past the checks below.
250 		var method = MethodSafety.effectiveMethod(req.getMethod(), req.getQueryString(), req::getHeader);
251 		if (! isStateChanging(method))
252 			return BoundaryResult.ALLOWED;
253 
254 		var origin2 = req.getHeader("Origin");
255 		if (ib(origin2))
256 			return reject(BoundaryReason.ORIGIN_MISSING, 403,
257 				"A state-changing request must carry an 'Origin' header of '%s'.", origin);
258 		if (! origin2.equals(origin))
259 			return reject(BoundaryReason.ORIGIN_MISMATCH, 403,
260 				"Request 'Origin' is not this server's origin '%s'.", origin);
261 
262 		// The presented value is deliberately not echoed back: it is caller-controlled, and a rejection message is
263 		// rendered into a response body and a log line, neither of which should carry attacker-chosen text.
264 		var fetchSite = req.getHeader("Sec-Fetch-Site");
265 		if (fetchSite != null && neq(fetchSite, "same-origin"))
266 			return reject(BoundaryReason.FETCH_SITE_NOT_SAME_ORIGIN, 403,
267 				"Request 'Sec-Fetch-Site' must be absent or 'same-origin' on a state-changing request.");
268 
269 		if (! BoundaryChecks.isJson(req.getContentType()))
270 			return reject(BoundaryReason.CONTENT_TYPE_NOT_JSON, 415,
271 				"A state-changing request must use content type '%s'.", JSON_CONTENT_TYPE);
272 
273 		var presented = req.getHeader(csrfHeader);
274 		if (ib(presented))
275 			return reject(BoundaryReason.CSRF_TOKEN_MISSING, 403,
276 				"A state-changing request must carry this server's CSRF token in the '%s' header.", csrfHeader);
277 		if (! token.matches(presented))
278 			return reject(BoundaryReason.CSRF_TOKEN_MISMATCH, 403,
279 				"The CSRF token in the '%s' header is not this server's token.", csrfHeader);
280 
281 		return BoundaryResult.ALLOWED;
282 	}

284 	/**
285 	 * Whether a WebSocket handshake's {@code Host} values match this boundary's authority.
286 	 *
287 	 * <p>
288 	 * A real {@code Host} header is compared as written, ignoring case, first value only: the same rule as
289 	 * {@link #check(HttpServletRequest)}.  A value synthesised from an HTTP/2 (RFC 8441) handshake's request URI is
290 	 * compared by parsed host and port instead, filling a missing port from the handshake's scheme and the
291 	 * authority's from {@code http}, which is this boundary's own scheme.  An authority that does not parse never
292 	 * matches.
293 	 *
294 	 * @param hosts The handshake's {@code Host} values.  Must not be <jk>null</jk>.
295 	 * @param scheme The scheme of the handshake's request URI.  Can be <jk>null</jk>, which matches only a value that
296 	 * 	carries its own port.
297 	 * @return <jk>true</jk> if the handshake is addressed to this boundary's authority.
298 	 */
299 	public boolean acceptsHandshakeHost(HandshakeHosts hosts, String scheme) {
300 		reqnn("hosts", hosts);
301 		if (hosts.values().isEmpty())
302 			return false;
303 		var value = hosts.values().get(0);
304 		return hosts.synthesised() ? matchesAuthority(value, BoundaryChecks.handshakeScheme(scheme)) : authority.equalsIgnoreCase(value);
305 	}
306 
307 	/** Whether a synthesised {@code host[:port]} names the configured authority, after filling default ports. */
308 	private boolean matchesAuthority(String value, String scheme) {
309 		var actual = BoundaryChecks.parseHost(value);
310 		var expected = BoundaryChecks.parseHost(authority);
311 		if (actual == null || expected == null)
312 			return false;
313 		// This boundary is plain HTTP: its own origin is "http://" + authority.
314 		var actualPort = actual.port() >= 0 ? actual.port() : BoundaryChecks.defaultPort(scheme);
315 		var expectedPort = expected.port() >= 0 ? expected.port() : BoundaryChecks.defaultPort("http");
316 		return actualPort > 0 && actual.host().equals(expected.host()) && actualPort == expectedPort;
317 	}

319 	/**
320 	 * Whether a request method is treated as state-changing, and therefore subject to the write checks.
321 	 *
322 	 * <p>
323 	 * {@code GET}, {@code HEAD}, {@code OPTIONS} and {@code TRACE} are read-only.  Everything else, including an
324 	 * unrecognized method, is state-changing.
325 	 *
326 	 * <p>
327 	 * Delegates to {@link MethodSafety#isSafe(String)} rather than carrying its own copy of the safe-method set.
328 	 * The startup check that refuses a {@link Mutating @Mutating} operation bound to
329 	 * a safe method reads the same definition, and a boundary that disagreed with that check about which methods
330 	 * are writes would silently defeat both.
331 	 *
332 	 * @param method The request method.  Can be <jk>null</jk>, which is treated as state-changing.
333 	 * @return <jk>true</jk> if the method is subject to the write checks.
334 	 */
335 	public static boolean isStateChanging(String method) {
336 		return ! MethodSafety.isSafe(method);
337 	}

372 	/**
373 	 * The headers an in-process client must add when calling this application's own loopback port.
374 	 *
375 	 * <p>
376 	 * An application that calls back into itself over HTTP &mdash; a mock of an external service mounted on its
377 	 * own port, a background task that drives its own API &mdash; is a state-changing caller like any other, and
378 	 * the boundary offers it no exemption (see the class javadoc's non-browser-callers section).  Rather than
379 	 * leaving each such caller to rediscover what the boundary wants, this returns it: the accepted
380 	 * {@code Origin} and the CSRF token under its configured header name.
381 	 *
382 	 * <p>
383 	 * {@code Host} is deliberately absent.  An HTTP client derives it from the request URI, so a caller already
384 	 * sending to this application's authority sends the right one; and {@code Host} is a restricted header that
385 	 * {@link java.net.http.HttpClient} refuses to set anyway.  The caller's remaining obligation is to send
386 	 * {@code Content-Type: application/json} on writes, which such a client is normally doing already.
387 	 *
388 	 * <p>
389 	 * This is not a back door.  It hands the token only to code already running inside this process, which could
390 	 * equally read it off {@link #token()}; it exists so that "call your own port correctly" does not become the
391 	 * argument for adding a path exemption.
392 	 *
393 	 * @return An immutable map of header name to value.
394 	 */
395 	public Map<String,String> selfCallHeaders() {
396 		return Map.of("Origin", origin, csrfHeader, token.value());
397 	}
398 
399 	/**
400 	 * The token a page must embed and a state-changing request must present.
401 	 *
402 	 * @return This boundary's token.
403 	 */
404 	public SynchronizerToken token() { return token; }

406 	private static BoundaryResult reject(BoundaryReason reason, int status, String message, Object... args) {
407 		return new BoundaryResult(reason, status, f(message, args));
408 	}

414 
415 		String authority;
416 		String csrfHeader = DEFAULT_CSRF_HEADER;
417 		SynchronizerToken token;
418 
419 		/**
420 		 * Constructor.
421 		 */
422 		protected Builder() {}
423 
424 		/**
425 		 * The authority every request's {@code Host} must equal, and from which the accepted {@code Origin} is
426 		 * derived.
427 		 *
428 		 * <p>
429 		 * Required.  Must be the exact host-and-port spelling the application links to, e.g.
430 		 * {@code "127.0.0.1:8790"} &mdash; the boundary accepts one spelling, not a set (see the class javadoc's
431 		 * canonical-origin section).
432 		 *
433 		 * @param value The expected authority.  Must not be <jk>null</jk>, blank, or carry a scheme or path.
434 		 * @return This object.
435 		 * @throws IllegalArgumentException If {@code value} is <jk>null</jk>, blank, or is not a bare
436 		 * 	host-and-port.
437 		 */
438 		public Builder authority(String value) {
439 			reqnn("value", value);
440 			var v = value.trim();
441 			if (v.isEmpty())
442 				throw iaex("Argument 'value' must not be blank.");
443 			if (v.contains("://") || v.indexOf('/') >= 0)
444 				throw iaex("Argument 'value' must be a bare host and port with no scheme or path: '%s'.", value);
445 			authority = v;
446 			return this;
447 		}
448 
449 		/**
450 		 * Convenience form of {@link #authority(String)} taking the host and port separately.
451 		 *
452 		 * @param host The bind host, e.g. {@code "127.0.0.1"}.  Must not be <jk>null</jk> or blank.
453 		 * @param port The bind port.  Must be positive.
454 		 * @return This object.
455 		 * @throws IllegalArgumentException If {@code host} is <jk>null</jk>/blank or {@code port} is not
456 		 * 	positive.
457 		 */
458 		public Builder authority(String host, int port) {
459 			reqnn("host", host);
460 			if (port <= 0)
461 				throw iaex("Argument 'port' must be positive: %s.", port);
462 			return authority(host.trim() + ":" + port);
463 		}
464 
465 		/**
466 		 * The header a state-changing request must carry the CSRF token in.
467 		 *
468 		 * @param value The header name.  Must not be <jk>null</jk> or blank.  Defaults to
469 		 * 	{@link LoopbackBoundary#DEFAULT_CSRF_HEADER}.
470 		 * @return This object.
471 		 * @throws IllegalArgumentException If {@code value} is <jk>null</jk> or blank.
472 		 */
473 		public Builder csrfHeader(String value) {
474 			reqnn("value", value);
475 			if (value.isBlank())
476 				throw iaex("Argument 'value' must not be blank.");
477 			csrfHeader = value.trim();
478 			return this;
479 		}
480 
481 		/**
482 		 * The token a state-changing request must present.
483 		 *
484 		 * <p>
485 		 * Required.  Normally one {@link SynchronizerToken#generate() generated} token per process, also embedded
486 		 * into every page the application serves.
487 		 *
488 		 * @param value The token.  Must not be <jk>null</jk>.
489 		 * @return This object.
490 		 */
491 		public Builder token(SynchronizerToken value) {
492 			reqnn("value", value);
493 			token = value;
494 			return this;
495 		}

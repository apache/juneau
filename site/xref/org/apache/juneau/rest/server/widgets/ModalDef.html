25  /**
26   * The declarative modal (dialog) a {@code present=dialog} row action opens &mdash; the payload the
27   * <b>modal-open confirmation fetch</b> returns.
28   *
29   * <h5 class='section'>A widget contract driven by a view-module runtime</h5>
30   * <p>
31   * This bean is a general widget contract and lives in this module, but the browser runtime that paints it ships with
32   * the rich-view module (it is part of that module's {@code juneau-views.js} monolith, which is not split apart here).
33   * So a page that opens one of these dialogs loads the view runtime; nothing in this module reaches back to it.
34   *
35   * <h5 class='section'>Safe-by-construction confirmation body</h5>
36   * <p>
37   * The confirmation body is <b>typed structured fields</b> ({@link #fields}: incident #, title, service, current
38   * status &mdash; the confirmation field set), server-rendered against the current, authoritative record and
39   * bound to the target identifier.  The {@code juneau-views.js} runtime paints each field's value with
40   * {@code textContent} &mdash; NEVER {@code innerHTML}, never raw markup, never the non-table panel-content sink.
41   * Live/remote data is attacker-influenceable (anyone who can title an incident or post in a watched thread) and this
42   * origin holds the CSRF token, so an HTML sink here would be stored-XSS&nbsp;&rarr;&nbsp;token-theft&nbsp;&rarr;
43   * arbitrary-write; typed fields painted with {@code textContent} close that off by construction.
44   *
45   * <h5 class='section'>The idempotency key rides here</h5>
46   * <p>
47   * {@link #idempotencyKey} is a server-minted key value, minted at modal-open and bound to
48   * {@code (action, targetId)}.  The runtime carries it verbatim on the submit so a double-click / re-submit / browser
49   * retry all collapse to one effect; the server checks that binding on submit and answers a mismatch with a named
50   * refusal, never a replayed success.  The minting/binding helper itself is a table-and-row-action concern and stays
51   * in the rich-view module, which is why this field is a plain {@code String} rather than that helper's type.
52   *
53   * <h5 class='section'>{@link #selfTargeted} &mdash; the opt-in for a key that targets itself</h5>
54   * <p>
55   * A dialog opened where there is <b>no row</b> (a ribbon-hosted dialog whose submit creates the thing it is about)
56   * has no artifact id to bind its key to at modal-open.  The rich-view module's key helper can mint a key whose
57   * bound target <i>is its own value</i>; {@link #selfTargeted} is the signal that tells the runtime to send that
58   * value as the submitted target instead of the row's id.
59   * <p>
60   * The signal has to ride on this bean, because it cannot be inferred from the wire: {@link #idempotencyKey} is an
61   * opaque string either way, indistinguishable in shape from an artifact-bound key's value.  It is therefore an
62   * explicit, additive, per-dialog opt-in &mdash; <b>not</b> a blanket runtime precedence rule.  A dialog that leaves
63   * this unset behaves exactly as it does today, <i>including</i> one that sets {@link #idempotencyKey} for an
64   * artifact-bound reason: it keeps sending the row's real id, which is what its own mint call bound.
65   * <p>
66   * Set it <b>only</b> on a modal whose key came from the self-targeted mint helper.  Setting it on a modal carrying
67   * an artifact-bound key silently discards the real target and makes the server's binding check vacuous.
68   *
69   * <h5 class='section'>{@link #keepOpenOnSubmit} &mdash; the opt-in for an in-dialog result receipt</h5>
70   * <p>
71   * By default the runtime closes a dialog at confirm-click time and then submits, so every dialog is gone before its
72   * result exists.  {@link #keepOpenOnSubmit} suppresses that close, and the runtime instead paints the write's
73   * <b>result</b> into the dialog that is already open &mdash; a <i>receipt</i>.
74   * <p>
75   * A receipt host is <b>non-submittable by construction</b>, not by convention: the runtime paints it with a distinct
76   * function that creates no confirm control at all, and it refuses to paint one whose payload carries a
77   * {@link #form}.  It is reached <b>only</b> after a committed write (an
78   * {@code ActionResult} whose outcome is {@code success}), so a result host can never appear for a write that did not
79   * happen.  A follow-up read-only form source is named by that result's {@code resultForm}.
80   * <p>
81   * The opt-in has to live here rather than on the action bean, because the confirm handler must decide whether to
82   * close <i>before</i> any response exists.  A dialog synthesized from a {@code confirm} string alone (no form-source
83   * URL) therefore cannot opt in &mdash; a receipt-bearing action must serve a real {@link ModalDef}.
84   * <p>
85   * Additive, and named degradation, accepted: an older runtime ignoring this flag closes the dialog and drops the
86   * receipt.  The write still happens; the receipt is simply not shown.
87   *
88   * <h5 class='section'>{@link #childActions} &mdash; the dialog-scoped child-action catalog</h5>
89   * <p>
90   * A {@code type="action"} form input names an action id, and the runtime resolves it against the enclosing view's
91   * row-action catalog.  A <b>stacked</b> step reached from inside an already-open dialog (a Review step in a wizard)
92   * has nothing legal to resolve against there: it is not a row action, and publishing it as one would surface it in
93   * every row's action menu.  {@link #childActions} is that missing catalog, scoped to <b>one open dialog</b>.
94   * <p>
95   * Scoping is <b>structural</b>, not a flag some menu builder has to remember to filter on: this catalog rides on a
96   * per-open payload, so the row-action menu and the ribbon resolver never see it and there is no exclusion logic to
97   * rot.  Resolution precedence is likewise fail-safe: the existing row-action check runs <b>first</b> and unchanged,
98   * so a served payload can never shadow &mdash; and thereby bypass the gating of &mdash; a declared row action.
99   *
100  * <h5 class='section'>{@link #chrome} and {@link #steps} &mdash; dialog styling and a built-in wizard</h5>
101  * <p>
102  * {@link #chrome} names a dialog chrome the page script registered with the runtime; the runtime hands that chrome the
103  * freshly built dialog parts so it can restyle them.  An unregistered name is ignored and the default chrome is kept.
104  * <p>
105  * {@link #steps} turns the dialog into a wizard: the runtime shows one {@link Step} at a time with Back and Next
106  * buttons, and the last step's button is the dialog's own confirm.  Both are additive-only and omitted from the wire
107  * when unset, so neither bumps {@link #CONTRACT_VERSION}.
108  *
109  * <h5 class='section'>Not a new row-action wire field</h5>
110  * <p>
111  * This is the response a row action's form-source URL returns, <b>not</b> a new field on the frozen row-action wire
112  * schema: the modal's declaration lives in this separately-served payload so the row-action contract stays frozen.
113  * The same reasoning is why {@link #keepOpenOnSubmit} and {@link #childActions} land here rather than on
114  * {@code RowAction} / {@code RibbonAction}, which stay frozen and untouched.
115  *
116  * <h5 class='section'>Example:</h5>
117  * <p class='bjava'>
118  * 	ModalDef <jv>modal</jv> = ModalDef.<jsm>create</jsm>(<js>"Acknowledge this incident?"</js>)
119  * 		.field(<js>"Incident"</js>, <jv>incidentNumber</jv>)
120  * 		.field(<js>"Title"</js>, <jv>incidentTitle</jv>)
121  * 		.field(<js>"Service"</js>, <jv>serviceName</jv>)
122  * 		.field(<js>"Current status"</js>, <jv>currentStatus</jv>)
123  * 		.form(FormDef.<jsm>ofTemplate</jsm>(<js>"servlet:/incidents/ack-form.ftl"</js>))
124  * 		.idempotencyKey(<jv>keyValue</jv>);
125  * </p>
126  *
127  * <h5 class='section'>See Also:</h5>
128  * <ul>
129  * 	<li class='jc'>{@link FormDef}
130  * 	<li class='jc'>{@link Widget}
131  * </ul>
132  *
133  * <h5 class='section'>The third named bar-slot host</h5>
134  * <p>
135  * {@link #barSlot} is the <i>third</i> named {@link BarSlot} attachment &mdash; alongside the rich-view module's page
136  * and row-detail hosts (that module never depends on this one, so they are not linked here).  Unlike those two
137  * &mdash; Java-only fields a server-side emitter paints directly, omitted from their wire &mdash; this modal itself
138  * <b>is</b> the wire payload the modal-open confirmation fetch returns, with no separate server-rendered pass the
139  * dialog could ride into.  So this field <b>is</b> carried on the wire (additive-only: {@code null} when unset, and
140  * its presence does not bump {@link #CONTRACT_VERSION}), and the {@code juneau-views.js} runtime paints the region
141  * and its dynamic-count sidecar client-side from the JSON, the same way it already paints typed confirmation
142  * {@link #fields} and {@link #form} controls &mdash; {@code textContent} only, never {@code innerHTML}.  The dialog
143  * anchors its own region immediately after the title (the {@code ANCHOR_DIALOG_TITLE}
144  * placement in {@code juneau-views.js}), owning that placement itself rather than leaning on the shared strip builder,
145  * exactly as the row-detail host owns its own ribbon-trailing relocation.
146  *
147  * @since 10.0.0
148  */
149 @BeanType(properties="contractVersion,title,fields,form,idempotencyKey,selfTargeted,barSlot,keepOpenOnSubmit,childActions,chrome,steps")

314 	 * One entry in a dialog's {@link ModalDef#childActions} catalog &mdash; a stacked step a {@code type="action"}
315 	 * input inside <i>this</i> dialog's form may open.
316 	 *
317 	 * <h5 class='section'>Dialog-presenting by construction</h5>
318 	 * <p>
319 	 * A child action carries no {@code present} field: opening a stacked dialog is the only thing it does.  A child
320 	 * with no {@link #form} is a legal confirm-only child dialog.
321 	 *
322 	 * <h5 class='section'>No gating vocabulary, on purpose</h5>
323 	 * <p>
324 	 * There is deliberately no {@code enabledWhen} here, for three independent reasons.  The rule type lives in the
325 	 * rich-view module, which this module must not reference.  A dialog opened where there is no row has no row data
326 	 * to evaluate against, so a field-keyed rule would fail closed forever with no signal to its author.  And the
327 	 * subject of a child step is the <i>draft in the open dialog</i>, not the parent row &mdash; so evaluating the
328 	 * parent row's data would answer a question nobody asked.  Gating a child step is the <b>server's</b> job at
329 	 * child-form-GET time; it already owns that GET and can refuse it.
330 	 *
331 	 * @since 10.0.0
332 	 */
333 	@BeanType(properties="id,label,form,endpoint,method,onSuccess,carryDrafts")
334 	public static class ChildAction {
335 
336 		/** The action id a {@code type="action"} input in this dialog's form names.  Required, non-blank. */
337 		public String id;
338 
339 		/** The label painted on the button that opens this child.  Required, non-blank. */
340 		public String label;
341 
342 		/**
343 		 * The child dialog's read-only form-source URL; omitted from the wire when unset (a confirm-only child).
344 		 *
345 		 * <p>
346 		 * Required if this child declares {@link #carryDrafts} &mdash; with no URL there is nothing for the draft
347 		 * query to ride on, so the drafts would vanish silently.
348 		 */

350 
351 		/** The child's submit endpoint; omitted from the wire when unset.  See {@link #endpoint(String)}. */

364 		 * <p>

700 	/**
701 	 * Fail-closed bean validation.
702 	 *
703 	 * <p>
704 	 * Requires a non-blank {@link #title} and a non-blank label on each {@link Field}; when a {@link #form} is present
705 	 * it delegates to {@link FormDef#validate()}.  Does <b>not</b> require {@link #contractVersion} to be set to
706 	 * {@link #CONTRACT_VERSION} (or set at all) &mdash; a modal whose version was explicitly cleared, or that
707 	 * arrived from a foreign producer that never set one, must not false-refuse on that alone.  Version-presence
708 	 * and structural well-formedness are deliberately independent properties (design note, &sect;5.4).
709 	 *
710 	 * <p>
711 	 * Also rejects, fail-closed at serve time rather than silently on the wire: a {@link Field#kind} outside the
712 	 * {@link #FIELD_KIND_TEXT text}/{@link #FIELD_KIND_CODE code} allowlist; a blank, duplicate or unlabelled
713 	 * {@link ChildAction} id; {@link ChildAction#carryDrafts} on a modal that declares no {@link #form} (nothing to
714 	 * collect <i>from</i>); and {@link ChildAction#carryDrafts} on a child that declares no
715 	 * {@link ChildAction#form} (nowhere to put them &mdash; the runtime would take its confirm-only branch, issue
716 	 * no GET, and the drafts would vanish silently).
717 	 *
718 	 * @throws IllegalArgumentException If this modal is not well-formed.
719 	 */
720 	@Override
721 	public void validate() {
722 		if (ib(title))
723 			throw iaex("ModalDef title must not be null or blank.");
724 		if (fields != null)
725 			for (var f : fields) {
726 				if (f == null)
727 					throw iaex("ModalDef field must not be null.");
728 				if (f.label == null || f.label.isBlank())
729 					throw iaex("ModalDef.Field label must not be null or blank.");
730 				if (f.kind != null && ! (eqa(f.kind, FIELD_KIND_TEXT, FIELD_KIND_CODE)))
731 					throw iaex("ModalDef.Field kind must be '" + FIELD_KIND_TEXT + "' or '" + FIELD_KIND_CODE
732 						+ "', not '" + f.kind + "'.");
733 			}
734 		validateChildActions();
735 		validateSteps();
736 		if (chrome != null && chrome.isBlank())
737 			throw iaex("ModalDef chrome must not be blank.");
738 		if (form != null)
739 			form.validate();
740 		if (barSlot != null)
741 			barSlot.validate();
742 	}
743 
744 	/** The {@link #steps} half of {@link #validate()}: non-blank unique ids and well-formed display fields. */
745 	private void validateSteps() {
746 		if (steps == null)
747 			return;
748 		var seen = new HashSet<String>();
749 		for (var st : steps) {
750 			if (st == null)
751 				throw iaex("ModalDef.Step must not be null.");
752 			if (st.id == null || st.id.isBlank())
753 				throw iaex("ModalDef.Step id must not be null or blank.");
754 			if (! seen.add(st.id))
755 				throw iaex("ModalDef.Step id '" + st.id + "' is declared more than once on this modal.");
756 			if (st.fields != null)
757 				for (var f : st.fields) {
758 					if (f == null || f.label == null || f.label.isBlank())
759 						throw iaex("ModalDef.Step '" + st.id + "' field label must not be null or blank.");
760 					if (f.kind != null && ! (eqa(f.kind, FIELD_KIND_TEXT, FIELD_KIND_CODE)))
761 						throw iaex("ModalDef.Step '" + st.id + "' field kind must be '" + FIELD_KIND_TEXT + "' or '"
762 							+ FIELD_KIND_CODE + "', not '" + f.kind + "'.");
763 				}
764 		}
765 	}

767 	/**
768 	 * The {@link #childActions} half of {@link #validate()}.
769 	 *
770 	 * <p>
771 	 * {@link ChildAction#of(String,String)} already argument-checks {@code id} and {@code label}; they are
772 	 * re-checked here as the wire-level backstop for a bean-deserialized instance that never went through the
773 	 * factory.
774 	 */
775 	private void validateChildActions() {
776 		if (childActions == null)
777 			return;
778 		var seen = new HashSet<String>();
779 		for (var c : childActions) {
780 			if (c == null)
781 				throw iaex("ModalDef.ChildAction must not be null.");
782 			if (c.id == null || c.id.isBlank())
783 				throw iaex("ModalDef.ChildAction id must not be null or blank.");
784 			if (c.label == null || c.label.isBlank())
785 				throw iaex("ModalDef.ChildAction label must not be null or blank.");
786 			if (! seen.add(c.id))
787 				throw iaex("ModalDef.ChildAction id '" + c.id + "' is declared more than once on this modal.");
788 			if (Boolean.TRUE.equals(c.carryDrafts)) {
789 				if (form == null)
790 					throw iaex("ModalDef.ChildAction '" + c.id + "' declares carryDrafts, but this modal declares "
791 						+ "no form - there is nothing to collect drafts from.");
792 				if (c.form == null || c.form.isBlank())
793 					throw iaex("ModalDef.ChildAction '" + c.id + "' declares carryDrafts, but declares no form URL "
794 						+ "- a confirm-only child issues no form GET, so the drafts would be dropped silently.");
795 			}
796 		}
797 	}

799 	/**
800 	 * The serving-path hook every app {@code @RestGet} that returns a {@link ModalDef} should invoke.
801 	 *
802 	 * <p>
803 	 * {@link #contractVersion} is guaranteed present on every modal from construction, so this is <b>no longer
804 	 * required for versioning</b>.  It stays <b>strongly recommended</b> for one remaining duty and
805 	 * is <b>redundant-but-harmless</b> for another:
806 	 * <ul>
807 	 * 	<li><b>Non-REST producers</b> (a direct {@code Json.of(...)} serialization, or any consumer marshalling a
808 	 * 		modal outside a REST response) have no other gate: calling this is the only fail-closed structural
809 	 * 		{@link #validate() validation} they get, and skipping it means a malformed modal/form serializes as
810 	 * 		contract-<i>valid</i> with no complaint.
811 	 * 	<li><b>REST responses</b> are validated independently:
812 	 * 		{@link WidgetsMixin.WidgetValidationProcessor
813 	 * 		WidgetsMixin.WidgetValidationProcessor} calls {@link #validate()} on every REST response that is a
814 	 * 		{@code Widget}, fail-closed with a 500, whether or not the producing endpoint called this method.
815 	 * 		Calling it anyway is safe (validation is idempotent) and remains the only gate for the non-REST case
816 	 * 		above.
817 	 * </ul>
818 	 * When a {@link #form} is present it also re-stamps {@link #CONTRACT_VERSION} on the form and recurses into
819 	 * {@link FormDef#checked()}.
820 	 *
821 	 * @return This object.
822 	 * @throws IllegalArgumentException If this modal (or its form) is not well-formed.
823 	 */
824 	public ModalDef checked() {
825 		if (form != null) {
826 			contractVersion = CONTRACT_VERSION;
827 			form.checked();
828 		}
829 		validate();
830 		return this;
831 	}

24  /**
25   * The validated token model behind the console's FTL {@code <@theme>}/{@code <@token>} directives: an immutable theme
26   * name, an ordered map of leaf tokens (literals) and an ordered map of alias tokens (live {@code var()} references).
27   *
28   * <p>
29   * Applications don't build themes in Java. They author them in their FreeMarker chrome, and the directives build
30   * this object:
31   *
32   * <h5 class='section'>Example:</h5>
33   * <p class='bftl'>
34   * 	&lt;@console&gt;
35   * 		&lt;@theme name="light-red"&gt;
36   * 			&lt;#-- A leaf: a literal (or a var() resolved to one at build time). --&gt;
37   * 			&lt;@token name="--jc-pill-red-bg" value="#fdeceb"/&gt;
38   * 			&lt;#-- An alias: a reference that stays live in the browser's cascade. --&gt;
39   * 			&lt;@token name="--jc-tab-bar-bg" alias="var(--jc-card-bg)"/&gt;
40   * 		&lt;/@theme&gt;
41   * 		&lt;@main/&gt;
42   * 	&lt;/@console&gt;
43   * </p>
44   *
45   * <p>
46   * That is equivalent to the following, which is what {@code <@theme>} does internally after seeding the builder
47   * from the stock palette:
48   *
49   * <p class='bjava'>
50   * 	Theme <jv>theme</jv> = Theme.<jsm>create</jsm>(<js>"light-red"</js>)
51   * 		.token(<js>"--jc-pill-red-bg"</js>, <js>"#fdeceb"</js>)
52   * 		.alias(<js>"--jc-tab-bar-bg"</js>, <js>"var(--jc-card-bg)"</js>)
53   * 		.build();
54   * 	String <jv>css</jv> = ConsoleChromeMixin.<jsm>overrideBlock</jsm>(<jv>theme</jv>);
55   * 	<jc>// html:root{--jc-pill-red-bg:#fdeceb;--jc-tab-bar-bg:var(--jc-card-bg);}</jc>
56   * </p>
57   *
58   * <p>
59   * The five stock palettes ({@link #OPEN}, {@link #LIGHT_RED}, {@link #LIGHT_BROWN}, {@link #RED}, {@link #GRAY})
60   * are selected by name: {@code <@theme name="gray">} in FTL, or {@code ConsoleChromeMixin.create().theme("gray")}
61   * for the served {@code chrome.css}.
62   *
63   * <h5 class='section'>The two channels:</h5>
64   * <p>
65   * The contract in one sentence: <b>a leaf is always a literal; an alias is always a reference; and no token name
66   * is declared by both.</b> The two channels are disjoint by <i>value shape</i> rather than by convention, and each
67   * carries its own validation:
68   *
69   * <table class='styled'>
70   * 	<tr><th>&nbsp;</th><th>leaf ({@link #getTokens()})</th><th>alias ({@link #getAliases()})</th></tr>
71   * 	<tr><td>example</td><td><c>--jc-accent: #b45309</c></td><td><c>--jc-tab-bar-bg: var(--jc-card-bg)</c></td></tr>
72   * 	<tr><td>value shape</td><td>literal</td><td>reference</td></tr>
73   * 	<tr><td>validated by</td><td>{@code CssValueGrammar}'s accept-known-safe allowlist</td><td>the anchored
74   * 		{@code var(--jc-name)} recognizer ({@link Builder#alias(String, String)})</td></tr>
75   * 	<tr><td>emitted</td><td>escaped, via {@code CssValueEscaper}</td><td>verbatim &mdash; see
76   * 		<i>Injection safety</i> below</td></tr>
77   * </table>
78   *
79   * <p>
80   * The rule a theme author needs to remember: <b>a literal belongs in {@link Builder#token(String, String)}; a
81   * reference belongs in {@link Builder#alias(String, String)}.</b> To make {@code --jc-tab-bar-bg} be {@code #fff},
82   * declare it with {@code token()}. To make it <i>follow</i> {@code --jc-card-bg} through the live cascade,
83   * {@link Builder#alias(String, String) alias} it.
84   *
85   * <h5 class='section'>Why the alias channel exists at all:</h5>
86   * <p>
87   * A leaf cannot carry a derived token. {@link Builder#build()} recognizes a {@code var(--jc-name)} value as a
88   * reference and <b>resolves it to a frozen literal</b>, which snapshots the live CSS cascade at composition time
89   * &mdash; so a token that must <i>keep following</i> its target can never be a leaf. {@code
90   * ConsoleChromeMixin.OPEN_ROLE_ALIASES} is the framework's own answer to the same problem, but those are
91   * unconditional framework defaults rather than per-theme derivations. The alias map is the third channel:
92   * <b>consumer-authored derivations that survive to the wire as references.</b>
93   *
94   * <h5 class='section'>The var() asymmetry &mdash; read this before "unifying" the two paths:</h5>
95   * <p>
96   * These two adjacent channels have <b>opposite</b> {@code var()} semantics, deliberately:
97   * <ul class='spaced-list'>
98   * 	<li>A {@code var()} in a <b>leaf</b> is <b>resolved away</b> before the wire ({@link Builder#build()}), so the
99   * 		served declaration carries the literal. That is asserted by {@code
100  * 		ConsoleChromeMixin_OverrideBlock_Test.a05}, which pins that {@code --jc-tag-red-text:var(} never appears in
101  * 		the body.
102  * 	<li>A {@code var()} in an <b>alias</b> must <b>survive as a reference</b> in the served declaration. Freezing
103  * 		it to a literal would defeat the entire purpose of the channel.
104  * </ul>
105  * <p>
106  * So a change that "unifies the two {@code var()} paths" silently destroys this type's reason to exist. The same
107  * warning is repeated at the emission site ({@code ConsoleChromeMixin.overrideBlock}), because that is the other
108  * place the mistake is reachable from.
109  *
110  * <h5 class='section'>The dark channel:</h5>
111  * <p>
112  * A theme may also declare <b>dark accents</b> with {@link Builder#dark(String, String)}, read back through
113  * {@link #getDarkTokens()}. They apply on top of the shared dark neutral layer, when the page is in the dark scheme.
114  * Only literals are accepted: a {@code var()} would resolve against the light palette, which would bake the wrong
115  * value into the dark scheme. The stock themes use the channel to keep their link, focus and accent colours
116  * legible on a dark surface.
117  *
118  * <h5 class='section'>Security:</h5>
119  * <p>
120  * Identifiers (theme name, token name, alias name) are rejected fail-closed by anchored {@code String.matches(...)}
121  * guards. Leaf values are validated by {@code CssValueGrammar}'s accept-known-safe allowlist grammar (not a
122  * {@code url(}-blocklist) and are escaped at emission time by {@code CssValueEscaper}. A leaf may also be a
123  * {@code var(--jc-name)} reference to another known token; {@link Builder#build() build()} resolves it to a
124  * concrete literal (own tokens shadowing {@link #OPEN}'s), so {@code var(} never appears in a {@link #getTokens()}
125  * value. An unknown reference, a cycle, or a chain longer than the resolution depth cap is a loud {@code build()}
126  * failure, never a silent fallback. Declared names in the reserved {@code --jc-chrome-*} namespace are rejected
127  * (see {@code rejectReservedChromeDeclaration}).
128  *
129  * <h5 class='section'>Injection safety of the alias channel:</h5>
130  * <p>
131  * Every alias value must match the fully-anchored {@code var(--jc-name)} shape ({@code VAR_REFERENCE}), which
132  * admits <b>exactly</b> this alphabet and nothing else: the three letters of {@code var} in either case, an opening
133  * paren, optional ASCII spaces, the literal {@code --jc-}, one or more of {@code [a-z0-9-]}, optional ASCII spaces,
134  * and a closing paren. (The recognizer's whitespace class can only ever match a plain space here, because every
135  * other character it would accept &mdash; tab, newline, carriage return, form feed, vertical tab &mdash; is a C0
136  * control character that {@code CssValueGrammar}'s belt has already rejected on the raw value, before this
137  * recognizer runs.)
138  *
139  * <p>
140  * So not one of {@code ;}, <code>}</code>, {@code "}, {@code '}, {@code \}, <code>/&#42;</code>, {@code url(} or a
141  * control character is <i>representable</i> in an accepted value &mdash; the emitted text is provably safe with
142  * <b>no escaper at all</b>. That is a strictly stronger claim than the leaf channel's "safe because we escape it",
143  * and it is the reason the channel is restricted to references rather than given an escaper of its own (escaping a
144  * {@code var()} reference would corrupt its parens).
145  *
146  * <p>
147  * A corollary worth stating: because an alias cannot carry a literal, the alias channel is <b>structurally</b>
148  * incapable of smuggling in a colour value, a font stack, or any other palette content. It can only ever point one
149  * name at another.
150  *
151  * @since 10.0.0
152  */

164 	/**
165 	 * Anchored recognizer for a {@code var(--jc-name)} Theme-layer reference, run on the post-belt (control-char
166 	 * rejected, comment-stripped, trimmed) value.
167 	 *
168 	 * <p>
169 	 * Fully anchored ({@code ^...$}) so a reference can only ever be the <b>entire</b> value, never a prefix or
170 	 * suffix of some larger value: {@code linear-gradient(var(--jc-a), #fff)} never matches this and is rejected by
171 	 * the unchanged grammar. There is no fallback branch &mdash; {@code var(--jc-x, #fff)} simply fails to match
172 	 * (comma inside the parens) and falls through to grammar rejection.
173 	 */
174 	static final Pattern VAR_REFERENCE = Pattern.compile("^[Vv][Aa][Rr]\\(\\s*(--jc-[a-z0-9-]+)\\s*\\)$");

528 	/**
529 	 * Seeds a builder with every token of {@code seed} under a new name. Used to author the stock palettes
530 	 * ({@link #LIGHT_RED}, {@link #LIGHT_BROWN}, {@link #RED}, {@link #GRAY}) from {@link #OPEN} without restating
531 	 * the whole map.
532 	 *
533 	 * <p>
534 	 * The seed's dark tokens are copied too.  A derived theme that declares its own accents should call
535 	 * {@code resetDark()} first, or it inherits the seed's dark accents.
536 	 */
537 	private static Builder deriveFrom(String name, Theme seed) {
538 		if (seed == null)
539 			throw iaex("Invalid theme seed: null.");
540 		var b = create(name);
541 		for (var e : seed.getTokens().entrySet())
542 			b.token(e.getKey(), e.getValue());
543 		for (var e : seed.getDarkTokens().entrySet())
544 			b.dark(e.getKey(), e.getValue());
545 		return b;
546 	}

596 	/**
597 	 * The single shared, fail-closed guard rejecting a declaration of a reserved chrome-scale token name, invoked on
598 	 * <b>every</b> path by which a token declaration can reach the served stylesheet.
599 	 *
600 	 * <p>
601 	 * <b>What it protects.</b> {@code juneau-views.css} declares one shared control-scale ladder
602 	 * ({@code --jc-chrome-control-height}, {@code --jc-chrome-font-size-1}, {@code --jc-chrome-glyph-size}, ...) at
603 	 * {@code :root}, and a contract test in that module pins it as declared exactly once so that every surface
604 	 * shares one ladder. A token block emitted here sits at {@code html:root}, which out-specifies that
605 	 * {@code :root} &mdash; so a consumer redeclaring a ladder step would win, render perfectly, and turn that
606 	 * contract into decoration with no test failing anywhere. Documentation is not a mitigation for that, so the
607 	 * rejection lives here.
608 	 *
609 	 * <p>
610 	 * <b>Where it fires.</b>
611 	 * <ul class='spaced-list'>
612 	 * 	<li>{@link Builder#token(String, String)} and {@link Builder#alias(String, String)}, at declaration &mdash;
613 	 * 		the only way a name enters a theme.
614 	 * 	<li>{@code ConsoleChromeMixin.overrideBlock(Theme)}, at emission &mdash; defense in depth; unreachable for a
615 	 * 		theme built by this class.
616 	 * </ul>
617 	 *
618 	 * <p>
619 	 * <b>It fires on the declared name only, never on a target.</b> Aliasing a stock-theme token <i>to</i> a ladder step
620 	 * is legal and useful; <i>declaring</i> a ladder step is not.
621 	 *
622 	 * <p>
623 	 * <b>The {@link Theme#OPEN} exemption.</b> The reserved namespace is {@code --jc-chrome-*} <i>except</i> the
624 	 * names {@link Theme#OPEN} itself already declares. Two names are exempt today:
625 	 * {@code --jc-chrome-bg} (page-chrome grey that predates the ladder) and {@code --jc-chrome-icon} (idle
626 	 * ribbon / paging glyph ink). Both are consumed by {@code chrome.css} and are legitimately overridable.
627 	 * Without the exemption this guard would reject {@link Theme#OPEN}'s own token
628 	 * set &mdash; and therefore every stock palette seeded from {@link Theme#OPEN}, which is the normal way
629 	 * to author a palette. The exemption is expressed against
630 	 * {@link Theme#OPEN} rather than as a hardcoded name list so it cannot drift: it needs no copy of the ladder's
631 	 * names (which live in a module this one deliberately cannot see), it stays correct if a chrome-named leaf is
632 	 * ever added to or removed from {@link Theme#OPEN}, and it fails <i>closed</i> for every new name &mdash; no
633 	 * ladder step is a {@link Theme#OPEN} token, and adding one could only ever happen through a reviewed edit to
634 	 * {@link Theme#OPEN} that its own pinned token count would surface.
635 	 *
636 	 * <p>
637 	 * A prefix test rather than an anchored {@code matches(...)}: by the time a name reaches here it has already
638 	 * passed a full-string {@code ^--jc-[a-z0-9-]+$} shape guard, so its alphabet is closed and
639 	 * {@link String#startsWith(String)} is total &mdash; there is no string that passes the shape guard, begins with
640 	 * the reserved prefix, and escapes this check.
641 	 *
642 	 * <p>While {@link #OPEN} itself is being built, {@code OPEN} is still {@code null} and the guard is skipped: the
643 	 * stock palette is the source of the exemption list, not subject to it.
644 	 *
645 	 * @param name The declared token name. Already shape-validated by the caller.
646 	 * @param source A short description of the channel the declaration arrived through, for the failure message.
647 	 * @throws IllegalArgumentException If {@code name} is a reserved chrome-scale token name.
648 	 */
649 	static void rejectReservedChromeDeclaration(String name, String source) {
650 		if (OPEN == null)
651 			return;
652 		if (name.startsWith(CHROME_TOKEN_PREFIX) && ! OPEN.getTokens().containsKey(name))
653 			throw iaex("Cannot declare reserved token '%s' (%s).  The '%s' namespace is the shared control-scale ladder declared by juneau-views.css; a token block served here out-specifies it.  Referencing one of these tokens is legal - declaring one is not.",
654 				name, source, CHROME_TOKEN_PREFIX);
655 	}

657 	/**
658 	 * Builder for {@link Theme}.
659 	 */
660 	public static final class Builder {
661 		private final String name;
662 		private final Map<String,String> tokens = new LinkedHashMap<>();
663 		private final Map<String,String> aliases = new LinkedHashMap<>();
664 		private final Map<String,String> darkTokens = new LinkedHashMap<>();
665 
666 		private Builder(String name) { this.name = name; }
667 
668 		/**
669 		 * Adds (or overrides) a single CSS custom-property token.
670 		 *
671 		 * <p>
672 		 * The value may be either a <b>literal</b> or a {@code var(--jc-name)} <b>reference</b> to another known
673 		 * token:
674 		 * <ul class='spaced-list'>
675 		 * 	<li>A literal is validated eagerly here by {@code CssValueGrammar}'s accept-known-safe allowlist grammar
676 		 * 		after normalization (trim &rarr; reject C0/C1/DEL &rarr; strip comments &rarr; reject {@code url(} in
677 		 * 		any spelling &rarr; grammar).
678 		 * 	<li>A value that, after that same normalization belt, matches {@code var(--jc-name)} is recognized as a
679 		 * 		reference and stored <i>unresolved</i> &mdash; it is resolved to a concrete literal at {@link #build()}
680 		 * 		time (its target may not be defined yet, e.g. a forward reference). {@code var()} is never a
681 		 * 		{@code CssValueGrammar} value shape; it is Theme-layer syntax recognized one layer above the grammar.
682 		 * </ul>
683 		 * Escaping happens later, at emission time, via {@code CssValueEscaper} (see {@code ConsoleChromeMixin}).
684 		 *
685 		 * <p>A declared name in the reserved {@code --jc-chrome-*} namespace that {@link Theme#OPEN} does not already
686 		 * declare is rejected.
687 		 *
688 		 * @param name The token name. Must not be <jk>null</jk> and must match {@code ^--jc-[a-z0-9-]+$}.
689 		 * @param value
690 		 * 	The CSS value &mdash; a literal, or a {@code var(--jc-name)} reference.
691 		 * @return This object.
692 		 * @throws IllegalArgumentException
693 		 * 	If the name is not in the legal shape (full-string {@code String.matches(...)}, not {@code find(...)}
694 		 * 	&mdash; {@code "--jc-foo;--bar"} must REJECT even though {@code "--jc-foo"} matches as a leading
695 		 * 	substring), if the value contains a control character or a {@code url(} production, or if the value is
696 		 * 	neither a {@code var(--jc-name)} reference nor one of the allowlisted CSS value shapes. A reference whose
697 		 * 	target is unknown, cyclic, or too deeply chained is instead reported at {@link #build()} time.
698 		 */
699 		public Builder token(String name, String value) {
700 			if (name == null || ! name.matches(TOKEN_NAME_PATTERN))
701 				throw iaex("Invalid theme token name: '%s'.  Must match %s.", name, TOKEN_NAME_PATTERN);
702 			rejectReservedChromeDeclaration(name, "theme '" + this.name + "' leaf token");
703 			// Recognition runs on the SAME post-belt string the grammar would see (one shared belt, no second
704 			// comment-stripping pass).  A reference is stored unresolved; a literal is validated eagerly, exactly
705 			// as before this feature existed.
706 			var normalized = CssValueGrammar.normalize(value);
707 			if (referencedName(normalized) != null)
708 				tokens.put(name, normalized);
709 			else
710 				tokens.put(name, CssValueGrammar.normalizeAndValidate(value));
711 			return this;
712 		}
713 
714 		/**
715 		 * Adds (or overrides) a dark accent token: a literal applied on top of the shared dark neutral layer when the
716 		 * page is in the dark scheme.
717 		 *
718 		 * <p>
719 		 * The name and value go through the same guards as {@link #token(String, String)}, with one difference: the
720 		 * value must be a <b>literal</b>. A {@code var()} reference is rejected, because the only thing it could
721 		 * resolve against is the light palette, which would bake the wrong value into the dark scheme.
722 		 *
723 		 * @param name The token name.  Must match {@code ^--jc-[a-z0-9-]+$}.
724 		 * @param value The CSS literal.
725 		 * @return This object.
726 		 * @throws IllegalArgumentException
727 		 * 	If the name is malformed or in the reserved {@code --jc-chrome-*} namespace without being a {@link Theme#OPEN}
728 		 * 	token, or if the value is a {@code var()} reference or is not one of the allowlisted CSS value shapes.
729 		 */
730 		public Builder dark(String name, String value) {
731 			if (name == null || ! name.matches(TOKEN_NAME_PATTERN))
732 				throw iaex("Invalid theme dark token name: '%s'.  Must match %s.", name, TOKEN_NAME_PATTERN);
733 			rejectReservedChromeDeclaration(name, "theme '" + this.name + "' dark token");
734 			// Literal only: CssValueGrammar has no var() shape, so a reference fails here rather than being resolved.
735 			darkTokens.put(name, CssValueGrammar.normalizeAndValidate(value));
736 			return this;
737 		}
738 
739 		/** Drops every dark accent, for a derived theme that declares its own set instead of inheriting its seed's. */
740 		private Builder resetDark() {
741 			darkTokens.clear();
742 			return this;
743 		}

745 		/**
746 		 * Declares an alias token: a name whose value is a live reference to another {@code --jc-*} token.
747 		 *
748 		 * <p>
749 		 * The target must be exactly one {@code var(--jc-name)} reference, with no fallback, no surrounding value
750 		 * and no second reference. It is stored after the shared normalization belt (trim and comment strip, with
751 		 * control characters rejected on the raw value) and emitted verbatim. Nothing dangerous is representable in
752 		 * that shape, so an alias needs no escaper. A literal belongs in {@link #token(String, String)}. A
753 		 * {@code var()} given to {@code token()} is resolved to its literal at build time; one given here is not.
754 		 *
755 		 * <p>
756 		 * A name may be declared by only one channel: {@link #build()} rejects a name given to both
757 		 * {@code token()} and {@code alias()}, in either order.
758 		 *
759 		 * <h5 class='section'>Example:</h5>
760 		 * <p class='bjava'>
761 		 * 	<jc>// Follows --jc-card-bg live, including any later override of it.</jc>
762 		 * 	<jv>builder</jv>.alias(<js>"--jc-tab-bar-bg"</js>, <js>"var(--jc-card-bg)"</js>);
763 		 *
764 		 * 	<jc>// Rejected: a literal belongs in token(), not alias().</jc>
765 		 * 	<jv>builder</jv>.alias(<js>"--jc-tab-bar-bg"</js>, <js>"#fff"</js>);
766 		 * </p>
767 		 *
768 		 * <p>A declared name in the reserved {@code --jc-chrome-*} namespace that {@link Theme#OPEN} does not already
769 		 * declare is rejected.
770 		 *
771 		 * @param name The alias name.  Must match {@code ^--jc-[a-z0-9-]+$}.
772 		 * @param target The reference.  Must be a single {@code var(--jc-name)}.
773 		 * @return This object.
774 		 * @throws IllegalArgumentException If the name or the target is malformed.
775 		 */
776 		public Builder alias(String name, String target) {
777 			if (name == null || ! name.matches(TOKEN_NAME_PATTERN))
778 				throw iaex("Invalid theme alias name: '%s'.  Must match %s.", name, TOKEN_NAME_PATTERN);
779 			rejectReservedChromeDeclaration(name, "theme '" + this.name + "' alias");
780 			if (target == null)
781 				throw iaex("Invalid theme alias target for '%s': null.", name);
782 			var normalized = CssValueGrammar.normalize(target);
783 			if (! VAR_REFERENCE.matcher(normalized).matches())
784 				throw iaex("Invalid theme alias target for '%s': '%s'.  Must be a var(--jc-name) reference.", name, target);
785 			aliases.put(name, normalized);
786 			return this;
787 		}
788 
789 		/**
790 		 * Builds the immutable {@link Theme}, resolving every {@code var(--jc-name)} reference to a concrete literal.
791 		 *
792 		 * <p>
793 		 * Resolution scope is this builder's own tokens, shadowing {@link Theme#OPEN}'s tokens (exact shadowing: a
794 		 * name defined on this builder wins outright, even if resolving that entry then fails &mdash; there is no
795 		 * silent fall-through to {@code Theme.OPEN}'s value for a shadowed name). Resolution runs on a copy of the
796 		 * token map, so a failed {@code build()} leaves this builder unchanged and retryable.
797 		 *
798 		 * <p>Rejects a name declared by both {@link #token(String, String)} and {@link #alias(String, String)}.
799 		 *
800 		 * @return A new {@link Theme} whose every token value is a resolved six-shape literal (the substring
801 		 * 	{@code var(} appears in none of them).
802 		 * @throws IllegalArgumentException
803 		 * 	If a reference names an unknown token, forms a cycle (the message carries the cycle path), or exceeds the
804 		 * 	resolution depth cap.
805 		 */
806 		public Theme build() {
807 			var resolved = resolveReferences();
808 			for (var n : aliases.keySet())
809 				if (tokens.containsKey(n))
810 					throw iaex("Theme '%s' declares '%s' as both a leaf token and an alias.  A name may be declared by only one channel.", name, n);
811 			return new Theme(name, resolved, aliases, darkTokens);
812 		}
813 
814 		/** Resolves every reference in a copy of the token map, preserving declaration order; never mutates {@link #tokens}. */
815 		private Map<String,String> resolveReferences() {
816 			var resolved = new LinkedHashMap<String,String>();
817 			for (var e : tokens.entrySet()) {
818 				var target = referencedName(e.getValue());
819 				resolved.put(e.getKey(), target == null ? e.getValue() : resolveReference(e.getKey(), target));
820 			}
821 			return resolved;
822 		}
823 
824 		/**
825 		 * Iteratively walks a reference chain from {@code firstTarget} to the literal it names, with exact shadowing
826 		 * (own tokens win over {@link Theme#OPEN}'s), cycle detection, and an independent hop cap; re-validates the
827 		 * resolved literal against the grammar as defense-in-depth.
828 		 */
829 		private String resolveReference(String definingName, String firstTarget) {
830 			// Theme.OPEN is null only while Theme.OPEN itself is being built - and it has no references, so this
831 			// fallback map is never actually consulted during that construction.
832 			var openTokens = Theme.OPEN == null ? Collections.<String,String>emptyMap() : Theme.OPEN.getTokens();
833 			var visited = new LinkedHashSet<String>();
834 			visited.add(definingName);
835 			var target = firstTarget;
836 			var hops = 0;
837 			while (true) {
838 				if (visited.contains(target))
839 					throw iaex("Theme token '%s' contains a cyclic reference: %s.", definingName, cyclePath(visited, target));
840 				if (++hops > MAX_REFERENCE_HOPS)
841 					throw iaex("Theme token '%s' exceeds the maximum reference depth of %d hops.", definingName, MAX_REFERENCE_HOPS);
842 				visited.add(target);
843 
844 				String targetValue;
845 				if (tokens.containsKey(target))
846 					targetValue = tokens.get(target);          // own map wins outright (exact shadowing)
847 				else if (openTokens.containsKey(target))
848 					targetValue = openTokens.get(target);
849 				else
850 					throw iaex("Theme token '%s' references unknown token '%s'.", definingName, target);
851 
852 				var next = referencedName(targetValue);
853 				if (next == null)
854 					// The resolved literal - and only that literal, with no var() present - is re-validated by the
855 					// unchanged grammar as defense-in-depth against a bad value hiding under a referenceable name.
856 					return CssValueGrammar.normalizeAndValidate(targetValue);
857 				target = next;
858 			}
859 		}
860 
861 		/** Returns the {@code --jc-name} a {@code var(--jc-name)} reference points at, or <jk>null</jk> if {@code value} is not a reference. */
862 		private static String referencedName(String value) {
863 			var m = VAR_REFERENCE.matcher(value);
864 			return m.matches() ? m.group(1) : null;
865 		}

867 		/** Renders a cycle path like {@code --jc-a -> --jc-b -> --jc-a} for a build-failure message. */
868 		private static String cyclePath(Set<String> visited, String repeated) {
869 			return String.join(" -> ", visited) + " -> " + repeated;
870 		}

29  /**
30   * Mixin that serves the first-party rich-view runtime assets &mdash; {@code juneau-views.js},
31   * {@code juneau-ribbon.js}, {@code juneau-renders.js}, {@code juneau-views.css}, the opt-in
32   * {@code juneau-regions.js} region-populate runtime, the opt-in {@code juneau-config.js}/{@code juneau-config.css}
33   * column-chooser runtime &mdash; each at its stable path, plus deprecated compatibility mounts
34   * for the two assets that have since moved to the widget module.
35   *
36   * <p>
37   * Compose into a host resource via {@link Rest#mixins() @Rest(mixins=ViewsMixin.class)}; the asset URLs then become
38   * available alongside the host's own endpoints, so browser pages can load the runtime without the application hosting
39   * it itself.  This mirrors the sibling {@code DataTablesMixin}/{@code ConsoleChromeMixin} serving pattern (those
40   * modules are not dependencies of this one, so they are not linked here).
41   *
42   * <h5 class='section'>What this ships (and what it deliberately does not):</h5>
43   * <p>
44   * Juneau's jars don't copy the <a class="doclink" href="https://datatables.net">DataTables</a> library or jQuery.  Only
45   * the thin, first-party runtime is served here; the DataTables, jQuery and Buttons files come from the WebJars that
46   * {@code juneau-rest-server-datatables} declares, served by {@code WebJarsMixin}.  The
47   * base {@code juneau-views.css} {@code .tag} chip is dependency-free (neutral, no colors); {@code console-ui}'s
48   * {@code chrome.css} themes the same {@code .tag.<domain>.<value>} classes when present, but this module takes
49   * <b>no</b> dependency on it.
50   *
51   * <h5 class='section'>Relocated: two assets now ship in the widget module</h5>
52   * <p>
53   * {@code juneau-calendar.js} and {@code juneau-calendar.css} are widget runtimes, not
54   * table runtimes, and their bytes now live in {@code juneau-rest-server-widgets} beside the bean contracts that
55   * drive them.  {@link WidgetsMixin} is where a new application gets them.
56   *
57   * <p>
58   * This mixin keeps a <b>deprecated</b> mount and path constant for each of the two so that an existing
59   * {@code @Rest(mixins=ViewsMixin.class)} application keeps working with no change: the mount reads the widget
60   * module's bytes off the classpath (that module is a compile-scope dependency of this one) rather than holding a
61   * second copy, so the body and the cache-buster are identical to what {@link WidgetsMixin} serves.  Composing both
62   * mixins is therefore harmless.
63   *
64   * <p>
65   * The relocation does <b>not</b> make that script standalone: it still resolves glyphs through this module's
66   * {@code juneau-icons.js} and pushes its popovers onto the ONE shared layer stack {@code juneau-views.js} publishes.
67   * A page loading the widget calendar runtime must still load this module's {@code juneau-icons.js} and
68   * {@code juneau-views.js} first.
69   *
70   * <h5 class='section'>Cache-busting + versioned URLs:</h5>
71   * <p>
72   * Each asset is served with a one-day {@code Cache-Control} and referenced from a page's {@code head=} block with a
73   * {@code ?v=<buildVersion>-<hash8>} cache-buster (see {@link #viewAssetUrl(String)}, or
74   * {@link #viewAssetUrl(RestRequest, String)} for a template-rendered consumer that needs the URL already resolved
75   * to an absolute, browser-fetchable form), where {@code hash8} is an
76   * 8-hex-char CRC32 of that asset's own served bytes, computed once and cached (classpath resources never change
77   * within a running JVM). Keying the buster off content rather than {@code buildVersion} alone matters for
78   * {@code -SNAPSHOT} builds: that version string is stable across dev rebuilds, so a version-only buster would keep
79   * serving a browser's stale cached copy after every rebuild - the content hash changes the instant the bytes do,
80   * with no SNAPSHOT special-casing needed. {@code buildVersion} is the framework's
81   * {@link Package#getImplementationVersion() implementation version}, falling back to {@code "dev"} when running from an
82   * unpackaged (IDE/test) classpath.  The served endpoint ignores the query string, so any (or no) {@code ?v=} still
83   * resolves to the same asset.
84   *
85   * <h5 class='section'>Contract-version handshake:</h5>
86   * <p>
87   * {@link #CONTRACT_VERSION} is the single wire-contract discriminator for a {@code VIEW_META} sidecar.
88   * {@code juneau-views.js} bakes in the same value so the client can fail loud when a served sidecar's
89   * {@code contractVersion} differs from the runtime's.
90   *
91   * <h5 class='section'>Mixin-only deployment:</h5>
92   * <p>
93   * The mount paths are pinned at the op level by {@code @RestGet(path=...)} on the serving methods; a class-level
94   * {@code @Rest(paths=...)} would be silently ignored under the mixin pattern.
95   *
96   * <h5 class='section'>See Also:</h5>
97   * <ul>
98   * 	<li class='jc'>{@link ViewTable}
99   * </ul>
100  *
101  * @since 10.0.0
102  */

870 	/** Maps a public asset path constant to its classpath resource constant (content-hashing only; routing itself is by {@code @RestGet(path=...)}). */
871 	@SuppressWarnings({
872 		"java:S3776" // Flat path-to-resource lookup table; one branch per asset, no nesting.
873 	})
874 	private static String resourceFor(String path) {
875 		if (eq(path, VIEWS_JS_PATH)) return VIEWS_JS_RESOURCE;
876 		if (eq(path, RIBBON_JS_PATH)) return RIBBON_JS_RESOURCE;
877 		if (eq(path, RENDERS_JS_PATH)) return RENDERS_JS_RESOURCE;
878 		if (eq(path, VIEWS_CSS_PATH)) return VIEWS_CSS_RESOURCE;
879 		if (eq(path, ICONS_JS_PATH)) return ICONS_JS_RESOURCE;

427 		// FIXED: writeBeanMap's inline-collection element-type check used to resolve elType from
428 		// getClassMetaForObject(value, cMeta)'s *runtime* result -- for a List<T> property that's always
429 		// the erased ArrayList meta (whose own getElementType() is Object) once value is non-null, unlike
430 		// an array whose component type survives erasure. elType now falls back to the property's own
431 		// declared cMeta.getElementType() for a Collection, so a List<Map> bean property still resolves to
432 		// nested "items { ... }" messages instead of degrading to a single scalar-list field whose entries
